## 7. 结论与 G2 建议（如实）

1. **质量**：A 基准 BLEU 31.2308；v2 的 C/D/E 分别 ΔBLEU -2.2790 [-4.0448, -0.7042] / -2.6436 [-5.7527, 0.6453] / -3.7644 [-6.7664, -0.5951]。C 仍然显著低于 A（LLM 最小修正仍偏离原句）；D/E 的负向不再全部显著，但**没有任何组的点估计超过 A**。
2. **核心判据**：D−C 与 E−D 在 v1、v2 两版中 CI 均含 0（无显著增益）；C→E 亦无显著增益。**当前 prompt 条件下，LLM 融合（含证据约束）没有质量收益证据。**
3. **成本-质量（G2 第三问）**：级联（默认 A，触发→E）触发率 28.00%，BLEU 30.7487，ΔBLEU vs A -0.4821 [-2.5316, 1.0609]（CI 含 0（不显著）），LLM 调用 14/0.28、tokens 22981；即级联能显著降低调用成本，但**质量没有优于纯 A**（不显著负向），因此按当前证据**不值得**为质量付出该成本。
4. **v1→v2 的效果**：prompt 迭代确实把 C/D 的 BLEU 从 v1 的 -4.55/-4.65 收窄到 -2.28/-2.64，但方向仍为负；这验证了「减少重写」的假设，也说明**仅靠 prompt 不能把整句融合变成正增益**。不再继续在同一 50 条上调 prompt（避免测试集过拟合）；若继续，必须换新样本/新 prompt 版本并重跑。
5. **G2 建议**：融合**暂不进入主链路**。保留可插拔接口；优先路线是 ① 继续 B（SLRT G2T/SLT，仍 BLOCKED）② 选择性/后处理式融合（仅在明确冲突时用证据修正，可先做 deterministic 规则，不依赖 LLM）③ 新独立测试集 + 人工语义评审（Round-1 包已就绪，待用户回填）后再评估是否值得启用 LLM 融合。
6. **还缺什么证据**：新独立测试集（非 retrospective_seen）、人工六槽位盲评（纠错/误改/严重错误率）、E05 的最长推理预算（E 组需要 4096 tokens）与真实级联批次 wall time（本轮为离线估计）。
