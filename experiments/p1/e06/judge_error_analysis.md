## 3. 已知规则缺陷

1. 中文数词/量词启发式会漏掉无量词数字与部分复合结构（如「两三」「几十」），也会被「一些/一样」类词干扰（已加 stoplist）。
2. 否定词表把「无」也计入（如「无论」会误报），属粗粒度极性信号。
3. 人物槽位只在 A、B 都出现代词且集合不同时触发；B 省略代词时不会触发，可能漏检性别误指。
4. 疑问只区分「有/无疑问标记」，不判断疑问词是否与问句类型匹配；且 B gloss 反问/省略会误报。
5. FUSE 只支持「单一数字槽替换」，不处理否定/人物/疑问的融合；无法修复措辞与多槽冲突。
6. 规则集合与阈值是在同一批 retrospective 数据上设计的，未做独立 dev 集选择；泛化需重做 signer 分组评估。

## 4. 为什么不能只靠 Rule-only

- 规则能捕获的显式槽位冲突有限：数字 122 次触发 / 误报率 0.4836；人物 164 次 / 误报率 0.2378。
- 主策略 missed-winner 率 0.0521（35/672）：被跳过的 A2 中只有 35 条本可给出更好文本（margin≥0.1），错停规模有限；但 missed-winner 只衡量「跳过是否亏」，不衡量「升级是否赚」——P2 的升级收益同样小（纠错率 0.0071），因为 A/A2 高度相关。
- 语义改写类错误（措辞、时态、语序、词义）没有可枚举的显式槽位，Rule-only 天然看不到；
  这部分需要语义仲裁（LLM/Jev）或模型侧置信度（Uni-Sign 当前 BLOCKED）。
