# 02 · 数据合同、日志、指标与人工评审规范

## 1. 统一的数据流和安全边界

```text
sample index (sample_id, video uri, timestamps, language hint)
    -> preprocessing per model
    -> EvidenceCandidate JSONL       [NO GT]
    -> Rule / Jev / LLM               [NO GT]
    -> FinalCandidate JSONL          [NO GT]
    -> EvaluationWorker (GT join)    [GT allowed; offline only]
    -> metrics / human review / Gate report
```

不要在输出到 Jev/LLM 的 JSON 中附加 `GT_sentence`、`GT_gloss`、`SLRT_WER`、`Uni_edit_sim`、`ground_truth` 等键，即使这些键在 Excel 中方便分析。推荐物理分离 `data/reference/` 和 `runs/<run_id>/predictions/`。

## 2. 目录约定

```text
experiments/p1/
  datasets/
    manifest_1086.csv      # sample ids / video paths / signer ids; do not include GT
    pilot_50.csv
  references/
    gt_1086.csv            # 仅离线评估读取
  configs/
    run_YYYYMMDD_name.yaml
  runs/
    <run_id>/
      manifest.json
      model_outputs.jsonl
      runtime_metrics.jsonl
      stream_events.jsonl
      fusion_outputs.jsonl
      errors.jsonl
      metrics.json
      report.md
```

模型和数据资产目录由用户环境决定：运行脚本必须允许配置相对路径/环境变量，不得把示例路径硬编码进推理实现。导出真实视频和关键点前应核对数据集许可。

## 3. 最小合同

### 3.1 `EvidenceCandidate`

见 `schemas/evidence_candidate.schema.json`。必须有 `sample_id`、`run_id`、`model_id`、`task`、`modality`、`window`、`output`、`status` 和模型/预处理修订。**真实的校准正确概率 `calibrated_reliability` 可以 `null`**。

模型输出区分：
- `CSLR`: `gloss_tokens` 按顺序排列，不假设已经是自然语言文本。
- `CSLT`: `text`、`spoken_language`；不把目标中文/葡语误作为 CSL/Libras 输入语言标签。
- `PARTIAL/FINAL`: 由 runtime window 状态单独定义；不能把 Excel 的 SLRT `final` 当作实时流的 Final 已被验证。
- `window.start_pts_ms/end_pts_ms`: 只有视频 FPS/PTS 实测后才能填写，未知设为 `null`。
- `quality.raw_score_value` 必须伴随 score_type，例如 `CTC_avg_logprob`、`token_mean_logprob`；不能填不知道来源的分数。

### 3.2 运行元信息

按 `schemas/run_record.schema.json` 记录 `git_sha`、`checkpoint_sha256`、`dataset_snapshot_sha256`、`preprocess_version`、`device`、`cuda`、`precision`、`seed`、`fps_source`、`metric_definition_version` 等字段。若无法获得，填 `null` 并把状态标记 `BLOCKED`/`PARTIAL`。

### 3.3 实验唯一键

- `sample_id` 是样本主键。
- `run_id + sample_id + model_id + attempt + window_id` 唯一标识单次模型输出，历史数据用 `run_id=imported_1086_legacy` 表明不含推理 timing。
- `candidate_id` 唯一标识待评价的一条中文句子，用于融合与人工盲审。
- 各种模型复用同一视频时，可有不同预处理哈希，但必须能回溯至相同 `sample_id` 和原始视频哈希。

## 4. 指标定义

| 指标 | 计算方法/说明 | 常见误区 |
|---|---|---|
| Corpus WER ↓ | `(ΣS+ΣD+ΣI)/(ΣN_gt_gloss)`；按语义可比的 gloss token 序列评估 | 不能将样本 WER 平均数当成 corpus WER |
| BLEU-4 ↑ | 统一的 corpus BLEU，保存 tokenizer、大小写与标点归一化、reference 数量及 sacreBLEU signature | 与原报告 24.82 不同 tokenizer 的 BLEU 不能直接求提升 |
| chrF ↑ | 统一 sacreBLEU chrF 配置并固定版本 | 不要将其等同于语义忠实度 |
| 严重语义错误率 ↓ | 人工标注人物/否定/疑问/数字/时间/动作/对象等错误，按每句汇总 | 流畅译文也可有严重语义错误 |
| 修复率 ↑ | `baseline 错且 fusion 对 / baseline 错`，对准明确的参照组 | 需与新增误改共同报告 |
| 误改率 ↓ | `baseline 对且 fusion 错 / baseline 对` | 不能只报提升样本数 |
| 误接受率 ↓ | `决策 ACCEPT 但人工/最终真值认为不可接受 / 所有 ACCEPT` | 评估路由器时不可看 oracle 答案 |
| 漏升率 ↓ | `应该升级却被 ACCEPT / 应该升级` | 升级真值需要人工/离线全模型对照定义 |
| Oracle 上限 | 只在离线按 GT 从候选中选择最佳 | 不能当作可部署的仲裁准确率 |
| RTF ↓ | `处理 wall time / 对应输入视频真实时长` | FPS 未知不能用帧数硬推视频时长 |
| 首稳时延 ↓ | 视频指定起点/动作发生时刻至首个“后续不再撤销”的稳定输出时刻，明确定义 | 首次临时字符 ≠ 首稳词/首稳句 |
| 端到端时延 ↓ | Capture/窗口等待 + queue + preprocess + forward + decode + fuse + display 的观测 wall interval | pipeline 处理各阶段时间可能重叠，不要无条件简单相加 |
| P50/P95 ↓ | 对符合实验条件的逐样本耗时分位数 | 排除失败样本会制造幸存者偏差，须同时报失败率 |
| 峰值 GPU VRAM ↓ | 记录单任务和模型常驻时的峰值，注明是否包含其他进程 | 不可将 total VRAM 当成模型使用量 |
| 校准质量 ↓ | Brier、ECE、reliability diagram、Risk-Coverage | 不同模型不同 score 定义，不可直接比较 raw_score |
| Missed Winner Rate ↓ | 被跳过模型若完整运行本应给出更好候选的比例；离线 shadow 实验计算 | 在线未运行模型时无法直接知道反事实 |

### 旧版与统一评估并存

把源 Excel 提供的 BLEU/chrF/WER 列为 `legacy_metric`；新脚本算出的统一规范指标叫 `canonical_metric`。若存在差异，不能写成“模型退化/提升”，要先核对 tokenization/归一化/样本过滤。

## 5. GPU 计时约定

- CPU/总耗时使用 `time.perf_counter()`；GPU 同步执行通过 `torch.cuda.synchronize()` 或 CUDA events，记录测量方式。
- 冷启动与热启动分开统计。预热后不改变 batch/precision/模型版本；固定同一数据输入顺序或记录 shuffle seed。
- `preprocess_ms` 分 GPU/CPU 可选，`decode_ms` 为视频解码/语言解码不同字段，不能混淆。推荐分别记录 `video_decode_ms`、`pose_ms`、`forward_ms`、`text_decode_ms`、`fusion_ms`、`queue_ms`、`e2e_ms`。
- 每段视频的捕获等待以真实 PTS 和墙钟同时记录；历史表中的 `frames` 无法决定时间。
- Python `asyncio` 并发仅证明任务调度并发，不说明同一张 GPU 的计算真正并行或更省资源。

## 6. 人工语义评审

**单位**：`sample_id + candidate_id + reviewer_id`；候选顺序随机，理想情况下评审时隐藏模型名称。

评分：0 完全错误/核心意思相反；1 主要错误；2 部分正确但关键缺漏；3 核心意思正确、局部表达偏差；4 语义完整忠实。

另按是/否/不确定标记：否定极性、疑问语气、人物指代、数量、时间、动作、对象、凭空添加实体，以及译文是否足以用于交流。每条候选保存评审人、日期和理由，重要样本至少双评审；分歧交由第三人仲裁。人工评审可以看到 GT，但它不可以被转回模型输入。

对质量比较，建议输出 **bootstrap 置信区间（按 signer 或语义簇分层/分组）**、paired sample 差异，并披露由于 signer 仅有 10 人导致的稳定性限制。不能仅依靠几个挑选出来的典型案例宣布融合有效。

## 7. 导出 Excel 说明

`templates/P1_1086_实验指标采集模板.xlsx` 包含历史三路预测的**来源列**以及新的空白字段。它是“测试运行记录的手工/脚本核验视图”，而不是 GPU 事实数据本身。推荐程序首先写 JSONL，再将 JSONL 导出 Excel，避免多人编辑同一 Workbook 造成内容覆盖。若对原表做修改，保留只读副本和文件 SHA256。
