# 01 · E00–E06 可执行实验协议

**共同约定**：每次实验启动时复制 `config/run_manifest.template.yaml`，填写 `run_id`、Git SHA、model checkpoint SHA256、dataset snapshot SHA256、硬件、fps、解码策略和预处理版本。每次运行输出不可变 JSONL/metrics 和日志；临时输出与正式结果分开。所有运行的状态为 `PASS/FAIL/BLOCKED/SKIPPED`，未运行不可填写 PASS。

## E00 · 模型资产、现有项目与运行环境审计（必须先做）

**输入**：现有项目 Git 仓库、当前 1086 数据、原版模型代码、权重引用/下载协议、目标 GPU/Docker。  
**问题**：当前源代码入口是什么？模型权重是否可用？不同环境能否共存？

**操作**：

1. `git status`、`git rev-parse HEAD`、`git ls-files` 审查项目；对比 README 与真实入口（先前资料对 Streamlit / 桌面 Tkinter 存在版本差异，禁止猜测）。
2. 为 `unisign_rgb`、`unisign_pose_released`、`slrt_twostream_slr`、候选 `slrt_twostream_slt`、`slrt_online`、遗留 RF 填模型注册表。
3. 每个条目记录来源 URL、模型目标任务（CSLT/CSLR/在线）、代码 commit、权重 SHA256、许可证、输入形状/采样率、关键点规范、可访问性、是否真正可运行。
4. 在隔离 Docker/conda 环境做 CPU/GPU 基本导入与 1 条 smoke；确认 torch/CUDA/视频库，防止不同仓库依赖互相覆盖。
5. 记录目标机器 GPU 型号、驱动、总显存、空闲显存、docker GPU passthrough、系统 FPS 测量能力。远程 Docker 机器通过用户已配置的方式访问，文档不可写入 SSH 密钥或主机秘密。

**成果**：`model_registry.yaml`、`environment_manifest.json`、`inventory_report.md`、权重许可证/可用性判断。  
**退出门槛**：各模型资产 `READY/BLOCKED` 清晰，至少一条 Uni-Sign 视频路径和一条 SLRT Gloss 路径能从具体可访问输入完成 smoke；其余缺少权重明确追踪，不得伪造可用性。

## E01 · 预处理一致性及推理可复现性（P0）

**输入**：Pilot 50 视频及既有三路结果；对应 checkpoint。  
**分支**：U1 Uni-Sign RGB/video；U2 Uni-Sign released pose；S1 SLRT TwoStream-SLR HRNet/本地对齐；S2（可选）复核官方 crop/关键点工具。

**步骤**：

1. 从原始视频计算 SHA256、准确帧数、PTS/FPS、尺寸、颜色空间、裁剪参数；保存 `video_probe.csv`。
2. 完整追踪前处理流程：读取 → 裁剪 → resize → 采样 → 姿态提取 → 归一化 → 模型张量，明确缺失点、左右手次序、身体坐标、时序长度。
3. 用与既有实验相同的模型、权重、decode 配置重跑 Pilot 50；记录 prediction、序列文本、logit 可用性及每步耗时。
4. 对比历史结果：UTF-8、标点、空格分别统计 `原样匹配`、`规范化匹配`、`输出内容差异`；对模型的随机性另做 repeatability 检查。
5. 仅在参考路径跑通后进行替换试验：实时摄像头/MediaPipe 与 HRNet 或官方输入规范对照，量化性能损失；禁止偷偷替换训练时骨架表示。

**指标**：输入帧数及 PTS 一致率、预处理成功率、文本匹配率、每例推理成功率、归因明确的差异数。  
**操作性通过规则**：Pilot 50 无未解释的静默失败；与参考结果不一致的样本有日志/版本/输入差异解释。推荐将规范化完全匹配率 ≥95% 作为调查起点而非论文阈值；低于此值优先排查，不要进入公平质量比较。  
**成果**：`reproduction_report.md`、`preprocess_audit.csv`、`predictions_pilot.jsonl`。

## E02 · 同任务翻译基线与互补收益（P0）

**研究假设**：句子生成与 Gloss 两类证据可以在一些样本上互补，但并不保证融合一定提升。

| 组别 | 输入推理链 | 可用性/备注 |
|---|---|---|
| A | Uni-Sign RGB → 句子 | 旧 Excel 已有 1086 预测，可直接回放 |
| A2 | Uni-Sign released pose → 句子 | 旧 Excel 已有 1086 预测；须标记发布姿态而非视频重提取 |
| B | SLRT Gloss → 固定 Gloss-to-Text → 句子 | 开发确定性/冻结版本翻译模块；可优先复用现成训练成果 |
| C | SLRT TwoStream-SLT → 句子 | 官方实现有翻译模型，**本地 checkpoint 可用性和依赖待 E00 验证** |
| D | SLRT Gloss → LLM → 句子 | 检查单一路 Gloss 的重建能力 |
| E | Uni-Sign RGB → LLM → 句子 | 控制“仅语言润色带来的收益” |
| F | Uni-Sign RGB + SLRT Gloss → LLM → 句子 | 检查双模型独立信息增益 |
| G | 双模型 + 证据约束 + LLM | 检查严重语义错误与误改风险 |

**步骤**：

1. 冻结当前 1086 条原始预测为 `historical_1086` 只读；缺失 B/C/D/E/F/G 输出不填假值。
2. 把现有 A、A2 预测和参考句子仅在 EvalWorker 中加载，运行既有 metric 的复核；额外计算统一指定的 `sacreBLEU corpus BLEU-4`、`chrF`。保存原始 24.82 作为 `legacy_reported_bleu4`，如 tokenizer 不同必须重新标记指标来源，**不得直接当同一统计口径的改进量**。
3. 若使用固定 Gloss-to-Text，优先验证它对 **GT Gloss → Text** 的上界能力（该结果仅作诊断，绝对不能进入测试期输入）；再输入 SLRT 预测 Gloss 得出 B。
4. 若 C 的权重可用，运行同一视频集合、相同参考句子及相同评价工具；同时记录与 A、B 的重叠错误。
5. 做语义融合 D/E/F/G：prompt、LLM 模型、温度和解码参数固定；对 `sample_id` 建立无 GT 的输入 JSON；关键槽位包括人物、否定、疑问、数量、时间、动作和对象。
6. 输出每条分支的文本、失败状态、词汇证据来源。统计严格的 **错误纠正数、正确译文被改错数、严重误译数**；人工审阅时随机候选顺序。
7. 计算两候选“GT oracle”：仅离线按真实答案在 A/B/C 中挑选较好的译文，作为**理论潜力**，而非可部署方法。

**指标**：统一口径 corpus BLEU-4、chrF、人工语义 0–4 分、关键事实完整正确率、误改率、纠错率、严重误译率、额外 LLM tokens 和耗时。  
**重要对比**：`F vs E` 衡量加入 SLRT 证据相对于普通 Uni-Sign→LLM 的增益；`G vs F` 衡量证据约束；`C vs A` 判断 SLRT 自带 SLT 是否值得单独纳入模型池。  
**成果**：`candidate_outputs.jsonl`、`fusion_ablation.csv`、`human_review.csv`、`translation_metrics.json`。

## E03 · 原始分数、校准和识别风险预测（P1；不阻塞 A/B）

1. 检查模型是否能输出 token/CTC log probability、Beam score、top1/top2 gap、模型熵；描述分数对象是帧、序列还是 token。
2. 不同模型不可共用分数阈值；先记录 raw score 与 score 定义，缺失填 `null`，不得填 1.0。
3. 离线为模型分别训练/选择可解释的错误风险映射；按 signer 分组交叉验证。不能使用同一测试样本既选阈值又报告最终效果。
4. 评估 ECE、Brier、可靠性图、错误发现率、coverage-risk 曲线，重要的是评估“错误 ACCEPT”率。
5. 如 logits 不可提取，则将此项标为 `BLOCKED` 或用文本稳定性特征作为弱信号，但严禁冒充 model confidence。

**成果**：`score_definition.md`、`calibration_results.json`、`risk_coverage.csv`。

## E04 · GPU 性能、显存和双模型调度成本（P0）

**执行设备**：真实目标 GPU（如果只有单 GPU，就只评估在该条件下的调度），固定驱动/镜像、FPS、batch=1 与输入帧数分桶。

1. 每个模型采集 3 组：冷启动 5 次（如果成本高可先 3 次）、预热后重复 ≥30 次、连续负载/队列 5–10 分钟（可按资源调整并记录实际次数）。
2. 计时区分：`T_decode`、`T_pose/preprocess`、`T_queue`、`T_forward`、`T_beam/text decode`、`T_fusion`、`T_render`，GPU 模型用 CUDA events / synchronize 避免错误的异步短计时。
3. 记录 GPU 空闲/峰值显存、模型驻留显存、OOM 次数、CPU/RAM、视频实际持续时长、wall time。CPU 侧用 monotonic/perf_counter。
4. 相同样本集做 `Uni-only`、`SLRT-only`、`serial`、`parallel`，记录并行总完成时间与峰值显存；并行不等于必然节省 GPU 计算或时延。
5. 在得到 E02 的质量数据后，离线模拟最保守的两级级联，比较预计模型跳过率/额外成本；不把模拟的成本标成实测延迟。

**指标**：P50/P95、E2E、每视频 GPU 忙时、峰值 VRAM、吞吐（样本/秒）、RTF、失败率、串行/并行增益。  
**成果**：`perf_trace.jsonl`、`hardware_report.md`、`parallel_vs_serial.csv`。

## E05 · 视频前缀压力测试与真正在线能力核验（P0 技术探针）

**前缀压力测试**：Pilot 50 每段分别输入 25%、50%、75%、100% **已观测前缀**，输出当前结果和分数；视频前缀不应被人为填充未来帧，模型如果无法接受短片则如实报告。

**在线系统测试**：优先检查 SLRT `Online` 分支的原生滑动窗口方法；Uni-Sign demo 的 `online_inference.py` 在文档中仍以 `--online_video {video_path}` 提供示例，不能据此直接宣布直播功能就绪。

1. 明确窗口大小、stride、能否保留历史状态、所需未来帧数和采集 FPS/PTS。
2. 对同一段流输入记录每个 `window_id`、start/end PTS、因果条件、timestamp、Partial Gloss/Text、Final、修订和拒判。
3. 时间信息至少包含：输入捕获与等待、窗口可用时刻、模型开始与结束、首个输出、首稳输出、最终确认的绝对时刻。
4. 计算 `first_stable_latency`、`P50/P95 E2E`、字幕撤销率、RTF；**不得把 window_processing_latency 作为最终字幕响应时间**。
5. 使用无手语、遮挡、左右镜像、不同采集帧率、两句无明显停顿的视频开展压力/负样本测试；检查串句和不合理自动补全文本。

**成果**：`window_events.jsonl`、`streaming_ability_matrix.md`、`future_frame_audit.md`。  
**判断**：若离线模型无法提供可接受的 Partial，可继续把它作为完整 utterance 的高质量后备翻译模型，而不强行改造成假流式。

## E06 · Rule/Jev/LLM 仲裁与调度可行性（P1 探索；先复用离线候选）

1. 从 E02 的 A/B/C/F/G 输出创建无 GT 输入，RuleJudge 先发现数字、否定、人物、动作的显式冲突。
2. Jev 只接收 `Choice/Score/Noul` 的结构化候选与冲突特征；验证汉语及 Gloss 可靠性；不向 Jev 直接发送视频。
3. 三种策略：`Rule-only`、`LLM-only`、`Rule/Jev -> LLM`。评测“应该升级却被 ACCEPT”的错误接受率与节省调用的成本。
4. `ACCEPT`、`FUSE`、`RETRY`、`UNCERTAIN` 必须由应用的确定性状态机执行；Jev 输出只作为输入信号。
5. 保留 5–10% shadow/full-run 样本（比例须在开发集确定）：即使路由想跳过另一路，仍跑全模型用于审计错停优胜率；训练/测试外推时单独记录。
6. 暂不做模型网络内部 Early Exit。第二路模型若已经开始一次不可抢占 GPU 前向计算，事后取消不能当成已节约计算。

**指标**：关键槽位冲突发现率、严重误译、误 ACCEPT 率、LLM 调用率、tokens、端到端时延、错停优胜模型率、相对于 full-fusion 的质量损失。  
**成果**：`router_ablation.jsonl`、`judge_error_analysis.md`、`policy_candidate.yaml`。
