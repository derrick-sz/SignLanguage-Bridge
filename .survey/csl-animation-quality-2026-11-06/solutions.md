# Solution Landscape: CSL 动画动作与人物画面优化

核验日期：2026-11-06（Asia/Taipei）。结论：优先采用“适合阅读手语的角色 + 少量修好的 CSL 完整短句 + 重定向/接触/表情校准”，保留现有工作台入口；以 Performs 作为播放器能力候选，以 WikiLibras 作为资产制作审核参考。先建立可比较的小样，再决定是否替换整个播放器。

证据范围：本地静态代码、两张历史截图、官网/GitHub 一手资料（`direct page retrieval`）。没有运行上游演示，也没有本轮新增质量、性能或语言通过结论。

## Categories

1. **资产制作与审核**：借鉴 WikiLibras，把参考视频、语言审核、动画制作、目标角色重定向和复审分开记录。[V1][V2]
2. **可配置人物与程序化实现器**：Performs/atelier 的参考价值是骨架与空间点标定、手部参数和非手控轨，而非直接取得一套 CSL 词库。[P1][P3][P4]
3. **时序/空间编排**：MMS 明确动作时长、过渡、保持与空间变化；比只排列片段更适合表达制作意图。[M2]
4. **数据驱动资产生产/生成**：Spoken2Sign 提供相应研究链路；应在本项目可审核基线建立后另行验证。[S1]

## What People Actually Use

这里的“使用”仅指一手资料所描述/实现的工作流，不是采用率调查或本轮实际运行结果。

- **WikiLibras 以人工制作与专家审核控制入库。** 官方流程先审核真人参考，再由动画制作者用指定角色制作三维动作，渲染后由专家复审；修改不合格动画会返回制作环节。[V1][V2] 值得借鉴的是把“能播放”和“目标手语表达通过”分开。
- **Performs 分开处理关键帧和脚本。** README、API 及 `js/KeyframeApp.js`、`js/ScriptApp.js` 确认两条模式。脚本文档描述手形、掌向、身体位置、手间关系、视线、头部和面部控制；这不证明所有通道都能直接叠加到任意 SMPL-X 片段。[P1][P2][P3]
- **Performs 需要角色配置。** 官方指向 atelier 生成配置；不能把旧角色骨骼名或旧接触点直接用到新比例人物上。[P1][P4] 关键帧源码的播放控制存在重新设定时间的行为，接入时还需保留本项目暂停/续播/拖动/停止语义，不宜一对一盲接 API。
- **MMS 使用显式时序及 IK 空间变化。** 文档定义 duration/transition、保持和双臂覆盖，并说明空间变化涉及 IK 与旋转回写，数值处理自身可能带来偏差。[M2] 普通 crossfade、IK 或空间偏移都不能单独证明 CSL 语言正确。
- **Spoken2Sign 的 3D 词典和连接器是依赖项。** 官方说明包含三维拟合、文本到 Gloss 和连接器训练/使用环节；普通文本模型或 2D pose 数据并非该整套能力。[S1] 本轮未安装、加载或训练这些组件。

## Frequency Ranking

本次按解决当前问题的优先级排序，**没有频率或普及度统计**：

1. 角色可读性、手部蒙皮与目标骨架标定。
2. 精选完整短句的手形、掌向、位置、接触及轨迹修正。
3. 有依据的面部/头颈/躯干轨与明确时间线。
4. 准确基线建立后的两段过渡，再到连续表达扩展。
5. 后续才评估大规模拟合、生成模型或整套引擎替换。

## Key Gaps

### 当前最值得做的优化

以下是建议，尚未实施；数量为试点规模建议，不代表当前已经有相应合格资产。

| 优先级 | 动作与人物画面一起改善的工作 | 如何判断有效 |
|---|---|---|
| P0 | 选 10–20 段有可靠参考的完整 CSL 短句，包含手指细节、双手接触、身体接触、快慢变化；表情缺参考的片段另标待补 | 同一批片段做改前/改后对照，逐段记录问题时间点，不先扩库 |
| P0 | 对比“修简现有 Godette”与“正常比例、简洁服装、清晰裸手、有完整手指绑定及可控面部的角色”；短发、袖口和配饰以不遮挡为准 | 在相同动作/视角下看清指缝、拇指、掌向和脸部；角色美术偏好单独记录 |
| P0 | 为目标角色建立 RigProfile：静止姿态、骨骼轴、掌面、拇指轴、比例与接触锚点；先检查中立、张掌、握拳、指向和接触 | 源视频/源姿态/目标角色三层对照，区分拟合错误、重定向错误与蒙皮错误 |
| P1 | 精选片段离线修手指关键帧与手腕；按动作阶段增加 IK 接触约束和必要避碰 | 检查双手、指尖/掌心与脸/胸的预期接触；避碰不得推掉有语义的接触 |
| P1 | 分开处理准备、核心运动、保持、收回；先去异常尖峰，再检查快速反转与短时手形 | 同时看原速和慢速；不能用更强平滑掩盖动作变形或时机错误 |
| P1 | 增加经审核的眉眼、视线、嘴部、头颈及躯干轨；骨骼或 Shape Keys 按角色能力选择 | 有可追溯参考与时间范围；眨眼/微笑不计作非手控语法实现 |
| P1 | Blender 中修蒙皮/动作并烘焙到目标角色动画，Web 端按时间播放，保存原始姿态和修正版 | 导出 GLB 后在实际播放器复验；编辑器内正常不代表导出正常 |
| P1 | 主视角以前方稳定半身为主，按完整活动范围取景；提供同步手部近景作辅助 | 全部指尖、头部、双手接触在横屏/窄屏可见；不逐帧追手造成画面晃动 |
| P2 | 基于已通过的单段，添加两段的保持/过渡和空间关系；之后再扩词典与文本规划 | 各语义片段与过渡分别审核；不靠删除未知词制造完整句子 |

人物角色的具体风格、是否更换角色和采用哪些第三方资产仍是待选择事项；“清晰手部、正常比例、简洁服装”是本轮提出的阅读目标，不是用户已经批准的美术方案。

### 应分开的验证

- **画面**：手形/面部可见、遮挡、背景和肤色/服装对比、画幅裁切；在同一动作与时间对照。
- **动作几何与时序**：手形、掌向、接触偏差、穿模、关节异常和停顿；按相同角色/骨架版本检查，原速与慢速都看。
- **语言可理解性**：由实际 CSL 使用者看完整动画并复述含义，首次理解任务隐藏提示字幕；画面偏好与语言正确分开计。评审身份和独立性记录清楚，AI/开发者检查不替代语言验收。
- **工程性能与控制**：在选定浏览器/设备记录加载时间、帧时间/掉帧和定位/暂停/续播/停止行为；插值到更高渲染 FPS 不代表手语信息变多。尚无本轮实测值或性能达标结论。

没有用 P-1 的识别 BLEU/WER 替代上述验收；没有重新解释历史实验成绩。若以后改识别或翻译模型，另按 P-1 的输入、参考版本及隔离协议评测。

## Contradictions

- **漂亮人物与正确动作不是同一结论。** 更换人物会改变长度和接触关系，旧动作质量批准不自动继承。
- **更平滑与更准确可能冲突。** 手指快速变形、重复和短暂停顿本身可以携带语言信息；滤波强度不能当质量分。
- **通用动画播放器不等于通用手语翻译器。** Performs 支持的格式不把当前中文文本或姿态自动变成合法 CSL 指令。
- **脚本与关键帧模式需要分别验证。** 本轮没有证据证明可直接将所有程序化面部/接触约束与当前动作轨任意混合；Performs README 对脚本生成画质也保留了与关键帧制作的差距说明。
- **“开源套件”不等于全资源同一授权。** VLibras、MMS、Performs 的代码许可及角色/动作/模型资源分别核对；外部公开示例不直接纳入当前资源库。
- **历史工程验收不等于当前画质验收。** 两张留存图只能支撑有限静态判断；本轮新的播放、性能、角色导出和语言测试均为 `NOT_RUN`。

## Key Insight

### 可选路线

| 路线 | 实际变化 | 取舍 |
|---|---|---|
| A. 修现有人物与精选片段 | 保持现有播放器；简化现有角色、校准绑定、修接触与动作 | 改动较小，便于同条件比较；受原网格、比例与面部表现能力限制 |
| **B. 新角色小样 + 精选资产修复 + 保留工作台（建议）** | 用适合手语阅读的角色做同批动作对照；借鉴 Performs 的人物配置与手部/非手控实现方式，修好再烘焙导出 | 同时覆盖动作和画面；需要角色、资产与目标骨架共同验收，先验证少量完整短句 |
| C. 用 Performs 替换显示内核 | 保留现有输入/资源审核，新增格式与控制适配层；分别验证关键帧/脚本模式 | 更便于探索通用角色和符号控制；需要转换格式、对齐控制语义，仍须解决 CSL 素材和语言问题 |

建议先执行 B 的小样比较，再以结果决定保留当前显示内核还是采用 C。VLibras 的借鉴点贯穿三条路线：先审可靠参考，制作目标角色动作，再审动画表达；不是直接移植它的 Libras 词典。MMS 的借鉴点是把“动作怎么衔接”变成明确可编辑的时间与空间信息。

本次止于调研和建议，没有制作新人物、修改播放器、重新拟合、训练或宣称改善已通过。角色选择、引擎替换及实施任务应在上述路线确定后形成具体设计。
