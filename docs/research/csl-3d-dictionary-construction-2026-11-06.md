# 中国手语三维词典建设建议（2026-11-06）

本文回答当前项目如何建设用于检索、组合和角色播放的 CSL 三维词典。是建设建议；未执行新的批量下载、三维重建、语义标注、训练或词条发布。现有动画工作区和未提交修改保持原状。

## 1. 词典的基本单位

建议采用“含义词条—动作实例—角色播放版本”三层关联，另保留完整短语库。中文文字是检索入口，词条要明确词义、语种和变体；不以单个汉字或 GLB 文件名定义含义。Gloss 是数据集采用的标记，需保留命名空间和对应关系，不直接当作语言无关的唯一词条 ID。

| 层级 | 关键记录 | 关系 |
|---|---|---|
| 含义词条 | entry_id、中文释义/别名、用法、CSL/变体、地域、规范参考版本、Gloss 映射 | 一个含义可有不同变体及多个演示；同一中文词的不同词义分别建条目 |
| 动作实例 | motion_id、源视频/数据集/sample ID/源 SHA、时间区间、签者编码、左右手、原始与修订动作版本、面部/头身/接触信息 | 一段连续视频可产生多个待审候选；每个实例保留上下文及边界审核 |
| 角色播放版本 | avatar/rig 配置、映射与处理版本、动作文件 SHA、GLB、取景/节奏、目标角色审核 | 同一个动作可以驱动多个角色；目标角色验收独立记录 |

现有 100 段包含完整句子，不能计作 100 个孤立词。用户指出的“我去开会汇报抽样调查落实的情况”目前是句级资产；若要提取其中某个词，必须回看对应原视频并确认词级边界。当前显示时序修复不自动产生词级标注或语言批准。

词目可以以[国家通用手语常用词表及其研制说明](https://www.moe.gov.cn/s78/A19/A19_ztzl/ztzl_yywzgfbz/guifanbzjs/201805/t20180521_336624.html)为规范参考，同时记录自然表达与地域变体。数据集词汇、某地表达及某版规范词表的对应关系需要手语使用者审核，不能仅凭中文标签自动合并。

## 2. 三条素材制作路线

| 路线 | 适用情况 | 需要核对 |
|---|---|---|
| 优先复用发布的三维拟合序列 | 数据集/sample ID 可对应、参数可解释、来源条件允许时 | 骨架/参数、手均值/PCA、坐标系、帧范围/帧率、原视频及质量 |
| 从已有真人视频重建 | 没有可用三维参数，或原拟合质量不足时 | 身体/双手/面部观测、遮挡置信度、相机、整段时序约束与手形 |
| 专项采集或人工修订 | 稀缺词、精细接触、遮挡严重或现有素材反复失败时 | 目标含义、自然演示、手指可见性；新采集来源与动作审核 |

[SOKE 官方项目页](https://2000zrl.github.io/soke/)提供 CSL-Daily 三维拟合数据入口。同日后续[资源核查](csl-reusable-resources-2026-11-06.md)已下载训练索引，并以 HTTP Range 抽查一个 SMPL-X 动作帧文件，确认三维 ZIP 约 2.69 GiB；未下载或验证整个包。训练索引有 17,438 个样本 ID 能匹配本机视频文件名，仍需核对原片内容、帧范围与参数表示，再决定哪些视频需要重建。公开拟合结果不等于无抽搐或已审核词典；仓库 CC BY-NC-ND 4.0 与具体数据授权需分别核对。

现有本机视频/标注清点见[语料扩充核查](../reports/animation-jitter-and-corpus-expansion-2026-11-06.md)：CSL-Daily 19,528 个 MP4、CE-CSL 5,988 个 MP4，另有 CSL-Daily 句级文本/Gloss/keypoints 文件。计数不等于可入库动作数；原片可能需要句段裁剪，多个句子可能含相同词。

当前 Uni-Sign、SLRT、TFNet 权重分别提供文本/Gloss 候选；RTMPose/HRNet 提供二维观测。它们可用于检索、候选分段和交叉核对，不能逆向导出三维词典。视频到三维拟合可以复用预训练初始化和逐段优化，不要求重训 Uni-Sign；完整拟合环境仍需单条实际验证。

## 3. 从语料到词条的制作流程

```mermaid
flowchart LR
    A[词目与原始标注] --> B[视频或已有三维序列]
    B --> C[对齐与候选分段]
    C --> D[统一动作与时序修订]
    D --> E[原片·骨架·角色对照审核]
    E --> F[词条索引与版本化动作库]
    F --> G[当前动画播放器]
```

1. **整理语义及来源。** 选择常用、可找到清晰原片的概念，明确用法与目标变体。清单绑定 dataset/sample ID、文本/Gloss、split、源文件 SHA、视频 FPS、原始时长和句段范围。已有标注保留为标签；模型预测另存，不覆盖标签。
2. **产生词级候选边界。** 有句级 Gloss 时，可研究匹配数据域的 TwoStream/SLRT S2G 强制对齐；必须将模型时间步经实际采样索引、裁剪偏移和帧率映射回原片。预测边界需人工回看，保留准备—主要动作—保持/回收及必要上下文。低置信边界保留为句级资产，不急于切词。
3. **复用或重建三维动作。** 先导入匹配的已有三维序列；缺失或不合格才从原片估计身体、双手和脸部信息，做相机/体型一致的整段拟合。遮挡帧依据观测置信度处理，不把二维 confidence 当作 z。手形、方向和关键保持帧作为约束；速度/加速度约束用于抑制拟合噪声，不能统一截断所有快速动作。
4. **统一资产协议。** 当前项目可输出 55 关节轴角姿态轨及独立面部/头身信息。记录骨骼顺序、parents/rest、轴角弧度或其他明确旋转表示、坐标轴、长度单位、FPS、有效帧与缺失区间。SMPL-X 的手部 PCA、均值添加、shape、相机与 root 变换依据生产者格式解释，禁止猜测。保留原始参数、修订轨和导出 GLB，分别计算摘要。
5. **时序、接触与重定向修订。** 原视频、标准骨架和目标角色按同一时间线对照。处理手臂反复翻转、肘部方向、手指尖峰、遮挡恢复与接触漂移；必要时在明确的接触区间锁定目标。平滑后的源轨必须同时用于重定向和 FK/IK，避免原始噪声重新引入。目标骨架绑定姿态、骨轴和手掌比例单独校准。
6. **审核后发布词条关联。** 一个词保留多个来源实例，优先选择手形清晰、完整、自然且与目标变体一致的代表动作；不以识别器最高分作为唯一依据。词条含义、源动作可读性、派生修订和目标角色各自审核，绑定具体版本及摘要。

该流程可借鉴 [Spoken2Sign 官方实现](https://github.com/FangyunWei/SLRT/tree/main/Spoken2Sign)：利用识别语料分段，估计三维动作词典，再连接 Text2Gloss、动作连接器与渲染。建立词典、训练生成模型和运行播放器是三个工作层次，逐层验证。

## 4. 入库记录与验收

每条可发布动作至少应能回答：这个词是什么意思，谁的哪次演示，原片哪一段，三维结果是哪一版，哪个角色上检查过，以及哪些项目仍缺失。

| 记录组 | 最少字段 |
|---|---|
| 语义 | entry_id、中文释义、别名、词义/用法、语种/地域变体、Gloss 命名空间与 ID |
| 来源 | dataset/sample ID、源 SHA、源时间范围/帧率、签者编码、split、来源与使用条件 |
| 动作 | motion_id、姿态格式/骨架版本、FPS、帧数、坐标系/单位、脸部/头身信息、已知接触及缺失信息 |
| 修订/播放 | 原始/修订动作 SHA、处理配置/版本、avatar SHA、rig 配置、导出 GLB SHA |
| 质量 | 边界审核、拟合/遮挡/连续性/手形/接触检查、语言审核、目标角色审核、审核对象摘要与记录 |

建议采用三种分开的状态，而非单个“通过”：

- **技术可用**：格式、帧数、有效数值、骨架、时间和导出一致性正确。
- **动作可读**：逐段与原视频比较，手形、方向、节奏、接触和非手控信息足以辨识，没有妨碍阅读的拟合异常。
- **语言已审**：由熟练聋人手语使用者/手语教师参与，遮字幕检查理解，再与原定含义核对；变体差异另记。此处建议至少两名审核者交叉复核，作为本项目建设建议，不是引用的统一行业门槛。

存在帧间角度峰值是复核线索，不直接等于错误。反译一致仅作辅助；程序测试、导出一致性和字幕相同都不能代替语言审核。缺少必要的面部/头身信息要标缺失，不能以默认中立脸冒充语义完整。

视频、人体模型、拟合数据和可发布派生文件分别记录来源与使用条件。[SMPL-X 官方实现](https://github.com/vchoutas/smplx)区分软件与人体模型获取，单纯安装 Python 包不等于具备全部模型文件。若后续训练或评测，继续保留数据划分；测试片段制作的词典不能用来宣称同一测试集上的独立泛化。

## 5. 接入当前工程

当前 `MotionRegistry` 按摘要保有动作资源，`plan_motion` 只支持完整表达匹配。建议保留这两者的现有能力，增加词条与动作的关联索引：

- 资源层继续通过 asset_id、源/派生摘要和白名单提供文件；词条层维护含义、变体与候选动作的对应。
- 先保持完整短语优先检索，逐步加入已审核孤立词；未审核的切词结果留在研究候选区。
- 词级组合另设 CSL 表达规划和过渡连接步骤，保留承载含义的手形/保持与面部时间线。孤立词词典本身不等于任意中文连续转译。
- 缺少所需含义或动作时返回明确缺口；不删除否定、数量或未知部分以强行播放。词条别名及相近中文词不能替代语义对应审核。

这些是建议的扩展，不是已经实现的词典接口或新审核状态。

## 6. 首期建议交付

先做 **50 个常用概念词条 + 20 个完整短语**，属于建议规模而非本次新增数量。优先办公/日常交流与现有应用场景，由审核者明确词目和表达；每词尽量保留两个清晰候选实例，并配上下文用例。

按当前本机条件的[时间与资源估算](../reports/csl-dictionary-resource-estimate-2026-11-06.md)分别列出复用三维数据和视频重建两条路线；重建速度仍是假设，批量前需样本标定。

首批交付物应包含：词目与变体表、源片/时间边界清单、三维参数和 GLB、同步对照页、逐段问题表、独立审核记录、版本化可发布清单和播放器检索入口。先实测这批的制作/修订/审核成本，再扩至数百词；不承诺未经试产核算的工期、GPU 成本或覆盖率。

当前 100 段可作为待整理的种子资产，但源视频缺失、含义未核对或严重抽搐的片段保持待审。近期指定片段的[时序修复候选](../reports/targeted-animation-temporal-repair-2026-11-06.md)仅改进显示连续性，不自动成为合格的孤立词条。
