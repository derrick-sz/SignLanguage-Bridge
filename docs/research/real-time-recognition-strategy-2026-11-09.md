# 实时手语识别策略评估

日期：2026-11-09。状态：**建议方案；未实施，未宣称实时验收通过。**

用户已明确首版体验目标：**动作过程中约1–2秒内看到词，停顿后补完整中文。** 因此推荐SLRT增量词与Uni-Sign句段翻译分工，LLM作为可选异步辅助。先验证吞吐与边界，再接入网页，不把录完再上传分片称作逐词实时识别。

## 当前证据及限制

1. [本轮SLRT + LLM实测](../reports/slrt-llm-scene-validation-2026-11-09.md)：6条原FPS回放均在EOF前交付词，首个提交词墙钟P50 1.54秒；但5条丢帧，词WER由同6条完整文件37.5%变成回放50%。LLM在EOF前提供中文0/6，完整文件调用P50 5.58秒且存在语义改坏。不能把LLM串在每次增量更新的必经路径上。
2. 本次继续读取同6条的profiling：姿态提取均值约25–32ms/帧、canonical_frame约3.2–3.6ms/帧、SLRT窗口约24.5–26.4ms/窗。stride=1稳态每到一帧运行一窗，当前实现串行相加约53–61ms，超过30FPS的33.3ms预算。这解释了积压风险；不是独立新性能实验，也不是精确GPU占用分解。
3. `SLRTRuntime`的帧准备缓存已经启用，不能再把“加入帧缓存”当作尚未完成的提速方案。`SLRTStream.feed()`发现丢帧/时间断点会中断解码上下文，不能把稀疏帧重编号成连续输入。
4. [同视频Uni-Sign对照](../reports/unisign-scene-comparison-2026-11-09.md)：整句文本指标更好，但完整文件HTTP P95 3.23秒；这不含录制时间。静止人物仍能触发误译，必须补活动和输入质量门控。
5. [P1前缀审计](../experiments/P-1/P1_EXECUTION_REPORT.md)：Uni-Sign不是原生增量提交模型；历史10句中6句到完整前缀才稳定，相邻前缀改写频繁。不能将每次窗口生成的整句直接追加为历史字幕。
6. 当前8765中文共享API能力仍为clip；SLRT已有独立`new_stream`。动画工作树的`RecognitionController`按完整File POST；`CaptionSession`按片段排队。HTTP读取上传字节的`request.stream()`不是模型增量推理。网页实时接入仍需要独立的会话和事件协议。

## 三种方案

| 方案 | 优点 | 代价及限制 | 建议 |
|---|---|---|---|
| SLRT增量词 + Uni-Sign句末中文 | 复用现有能力；明确分开词证据与整句译文；符合用户目标 | 必须解决SLRT积压、句界和单卡调度 | **首版优先** |
| Uni-Sign持续重译当前窗口 | 接入组件较少，能显示可修改整句草稿 | 前缀改写大，无法保证动作中可靠出词；每次完整视频重算昂贵 | 保留为实验对照 |
| 专用流式翻译训练：wait-k G2T或前缀训练/稳定重译 | 更贴近持续中文输出，有机会减少中间误差与改写 | 需要适配权重、训练及新流式评测；不能直接切换即承诺更好 | 第二阶段 |

SLRT上游提供[wait-k G2T实现](https://github.com/FangyunWei/SLRT/blob/main/Online/SLT/README.md)，但其[wait2示例](https://github.com/FangyunWei/SLRT/blob/main/Online/SLT/configs/g2t_wait2.yaml)是Phoenix/DGS→德语。本次本地SLRT资产检索只发现Phoenix G2T checkpoint，未发现可用的中文在线G2T。已有中文Text2Gloss生成权重也不能倒过来当Gloss2Text。后续须核验兼容中文权重，或用train/dev训练并以实际预测词的噪声分布适配；不能仅改语言代码。

[ReSCUE论文](https://arxiv.org/abs/2610.03022)将前缀/静止/多句训练、稳定重译和句子提交结合，并评测CSL-Daily。其思路适合长期连续中文方向；截至本次访问，[官方仓库](https://github.com/Tabiiiqwq/ReSCUE)只有README的“Coming Soon”，不是当前可直接部署的替代品。[StreamSLST](https://github.com/streamsl/StreamSLST)提供连续pose上的事件定位与翻译训练代码，可列为研究对照，本次未获得并核验适配本机的中文预训练权重。论文结果和作者时延均不作为本项目成绩。

## 推荐链路

```mermaid
flowchart LR
    V[实时视频与原时间戳] --> P[姿态提取与有界缓存]
    P --> S[SLRT增量识词]
    S --> W[临时词与已提交词]
    P --> B[活动检测与句段缓冲]
    B --> U[Uni-Sign句段翻译]
    U --> T[中文草稿与已提交译文]
    W -. 句段证据 .-> A[可选异步核对]
    T -. 原译文 .-> A
```

### 1. 视频连续输入，姿态分工复用

新增真正的会话输入，持续接收带序号、源时间戳、源epoch的帧或可增量解码的视频；返回词/句事件。不要等待MediaRecorder完整文件结束才启动识别，也不要把每个编码分片假设成独立可解码文件。

优先保留每个真实输入帧的时序。单人姿态提取与原始133点结果只做一次，按时间保存有界缓存；SLRT与Uni-Sign分别经过自己的坐标、点位和归一化适配。当前两路图像处理与坐标约定存在差别，**必须先验证共享前端等效性；无法等效时使用新协议并重评**。不能直接将SLRT的63点热图喂给Uni-Sign，也不能复用已经按另一模型归一化的数组。

Uni-Sign句末直接使用该句已缓存姿态，省去重新上传、解码与全段重复姿态提取；保留各自训练输入约定。现有Uni-Sign窗口有缓存，但文件API每次独立上传不能等同于共享流式姿态服务。

### 2. SLRT先达到持续处理预算

按测量顺序比较，避免一次改多项无法归因：

- 保留当前帧缓存与16帧训练窗口，先建立无LLM、无第二模型的持续回放基线。
- 验证人体检测框复用（候选detect_stride=3/5），姿态仍逐帧计算；人员变化、质量下降、换源时立即重检/清缓存。`RtmposeExtractor`已有可复用实现，SLRT前端当前未采用该策略。复用框会改变姿态输入，必须单独记录协议与识别变化。
- 比较阶段流水线调度与模型数值优化。ORT姿态与Torch窗口竞争同一GPU，增加线程不等于提高吞吐；以真实队列年龄和出词时延评判，不引用离线并行批处理加速。
- 如仍不够，评估**只调整预测锚点stride=1→2**，保持原始帧与时间戳。这与采集丢帧不同，但改变投票密度、未来等待和漏词风险，须独立评估；不默认同时降低vote_size。

不以增大queue_size解决吞吐。正常负载必须持续跟上；遇到断帧按输入不连续失效当前临时结果，明确报告过载，不把跳过的输入伪装为完整识别。

### 3. 句界采用多个信号，译文分阶段提交

SLRT持续显示词，不等停顿。句末候选结合归一化手部运动、姿态质量、已识别词的变化和blank证据；低运动持续约600–900ms仅作为初始待调参数。手语中的静态保持和思考停顿不天然等于句号，不能仅靠“手不动”硬切。

句段保留短前后上下文；每句有明确ID及修订版本。先显示中文草稿，满足边界与稳定性条件后提交该句，仍标记为机器译文、允许人工修改。词序列与中文分别展示，句末修订不冒充先前词已经识对。不要只因两次输出一致或模型生成句号就判断语义正确。

源缓冲、待译任务和字幕历史均有界；长度上限要与max_frames=256协议一起评估。长时间无可靠边界时保留词、显示待分句，提供手动结束句的后备入口，不能静默截断成一条已确认句。

### 4. 单卡优先服务增量路径，LLM异步

持续驻留识词与翻译实例，由一个协调器调度；不在每个片段反复切换全局中文active model。先验证宿主commit/显存余量与两模型预热，再测试单卡竞争。

姿态和SLRT处理优先，Uni-Sign只在句界或低负载时运行。只合并**同一句**过期草稿任务，不能把上一句尚未翻译的任务当成下一句的旧版本丢弃。换源、取消、模型切换和源epoch变更必须拒绝迟到结果；帧积压、句子待译和超时均可观察。

首版不等待LLM才显示词或译文。若保留LLM，仅异步进行有证据的语序建议/风险提示，保留原译文和实际词列。否定、数字、时间、人称等冲突应标出待核对，不能交给LLM任选一句作为事实；双方一致也不能当真值。最新版本拒答/失败时不得重新发布旧版本草稿。

## 实施顺序与验收目标

以下为**拟定目标，不是已经测得的能力**：

| 项目 | 首版目标及计时口径 |
|---|---|
| 首个可见候选词 | 有效动作开始到浏览器显示约1–2秒；候选可修订，不称语义正确 |
| 句末中文 | 人工标注的动作结束到浏览器提交译文P95≤2秒，包含停顿判定、排队和渲染 |
| 持续吞吐 | 实际输入FPS下至少连续10分钟正常负载无识别输入丢帧、积压不持续增长 |
| 队列等待 | 记录P50/P95、最大值与随时间趋势，初始目标P95≤200ms |
| 空白/静止 | 黑帧、无人、静止及非手语活动均专门统计误触发，不能只测正例 |
| 质量 | 固定视频对照词WER、译文指标和事实错误；单列否定、人称、时间、数字及模型互相改坏 |

先做当前原FPS回放的吞吐/姿态复用消融，再接stream会话协议和网页双层展示，最后加入可选LLM。预测步长、检测间隔等只在train/dev诊断集调，保留固定回归和新的未见签者验收集，不能在这30条已见test上反复调优后宣称泛化。

采集与浏览器显示尽量使用同一客户端单调时钟、事件回带帧序号，服务端另记阶段耗时；不要混用source timestamp和server wall clock。出词语义延迟需有人工词/动作边界的子集，`available_time`与工程final事件不代替真实词结束时间。

物理摄像头、新签者、自然连续表达、实际网络与共享GPU负载必须实跑；多句拼接回放只作工程诊断。当前6条回放的分位数不能作为稳定摄像头P95验收。本轮仅策略审计和文档，无新模型性能实验、无生产代码变更。
