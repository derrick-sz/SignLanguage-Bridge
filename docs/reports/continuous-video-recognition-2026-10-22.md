# 连续视频识别验证（2026-10-22）

## 结果与行为

已新增“连续识别视频流（无需停顿）”。持续取帧、真实活动观察、后台窗口推理和预览分别执行；无需确认停顿才调用模型。1.2–2.4 秒窗口、目标间隔 0.5 秒，只有一个模型任务，空闲后取最新窗口；不会排队识别过时画面。结果显示为可修正的当前窗口，保留原手动识别和停顿确认字幕流程。

双手不可见、质量丢失、来源时间缺口、暂停、取消、换源、停止模式都会清除候选或使在途结果失效；视频 EOF 也停止模式并取消迟到交付。结果年龄上限 3 秒，窗口最多 180 帧／96 MiB／宽 640。重载释义保留候选原始过期时间。正式字幕记录不由重叠窗口重复追加。先停止连续模式，再切换手语；模型加载时延后打开启动输入，避免短视频先播放完。

现有 TFNet 和 RF 仍使用原保存的完整片段预处理与 clip 能力声明，没有重训、改写权重或将连续跟踪关键点冒充冻结的 RF 提取协议。窗口结果不能作为原生流式解码、连续整句翻译或准确率验收。

## 诊断证据

旧端点逻辑的确定性回放：持续运动 4 秒没有提交，停止后约 0.667 秒才 ready。中文 8.2 秒完整文件 CPU 两次 6.33／6.67 秒，CUDA 为 2.36／2.12 秒，完整 logits 在容差内一致，argmax 和最终 token 相同。Libras 66 帧已采集片段为 1.95／1.10 秒，RF 本身约 5 ms，主要耗时是 MediaPipe。

这些是机制与单视频耗时证据，不能代替真人端到端 P95 或模型准确率。

## 使用

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_demo.ps1 -Language csl -Camera 0
```

可指定 `-Language libras` 或 `-Video "绝对视频路径"`。旧窗口需要重新启动后才包含新控件；直接运行时添加 `--continuous`，或输入与模型就绪后手动勾选主界面控件。
