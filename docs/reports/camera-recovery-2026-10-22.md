# 摄像头黑屏恢复与首帧就绪校验

## 结论

本次黑屏复现在应用外：旧 CPU 环境和 GPU 环境的 OpenCV 都能打开摄像头句柄，但读取首帧失败；独立 FFmpeg 指定 `2K USB Camera`、MJPEG／YUY2 两种原生格式也报 I/O 错误。Windows 识别到设备、权限为 Allow，探测时未发现活动摄像头使用记录。DirectShow 超时、MSMF 返回失败，关闭硬件转换也未恢复。

用户重新插拔 USB 后，原始探测立即恢复：两帧 640×480、时间戳递增、正常释放。证据支持本次故障位于设备／Windows 采集链路；没有据此断言具体线缆或驱动损坏。没有修改驱动、禁用设备、重置系统服务或终止用户进程。

应用同时存在“仅凭句柄打开便报告已就绪”的问题。本次修复为：`CameraSource.open()` 必须读到并验证首帧才成功；原始帧和采集时间缓存给第一次 `read()`，不丢弃或重新计时。失败立即按原有单所有者流程释放，关闭清除缓存。视频输入与模型预处理不变。

## 回归

- 三项源测试先 RED 后 GREEN：首帧失败不得 open 成功、合法首帧保留原时间并交给消费方、非法图像不得就绪。
- 会话级测试：首帧阻塞期间不得发布 `opened` 或设置 `source_active`；释放后正常就绪。移除首帧校验的负对照确实失败。
- 针对源、识别会话、关键点会话与连续识别的组合：77 passed。
- 完整 CPU 回归：714 passed、11 skipped、18 warnings，50.18 秒，退出码 0；已启用真实 RF 文件／captured_clip 一致性测试。跳过为 9 项未安装 Torch、1 项本地上游源缺失、1 项旧模型不分发。
