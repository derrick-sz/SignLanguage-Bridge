# 首批中国手语三维词典：时间与资源估算（2026-11-06）

按上一轮建议的 50 个概念词条 + 20 个完整短语估算。在已有三维素材可用的条件下，首批预留 5–10 个工作日；若主要从原视频重建，预留 10–20 个工作日。以下为规划预算，视频重建部分未在本机实跑，不是本机模型性能实测。

## 1. 估算范围与前提

- 当前平台：i5-14600KF、32 GB 内存、RTX5060 Ti 16 GB；GPU 基础已实测，完整视频重建环境尚缺，见[本机核查](local-csl-dictionary-readiness-2026-11-06.md)。
- 最终 70 条代表动作，复用现有人物和工作台；每词先选 2 段候选，20 个短语各 1 段，共 120 段候选。
- 候选词片段平均 4 s、短语平均 8 s，均按 25 FPS。候选素材总量为 `(50×2×4 + 20×8)×25 = 14,000 帧`，约 9.3 分钟；这是估算假设，不是已选素材的实际统计。
- 素材能匹配原片/含义，词级边界可复核。复用路线假定多数三维序列已有可读基础，常规返修可以覆盖；若大量缺手形、面部或原片，需重估或切换重建/补录路线。
- 包含首版词条索引、批量导入/检查、动作修订、发布清单和一轮常规复查；不包括重做角色美术、新拍视频、从零训练生成模型或完整处理全库原片。
- 工期按 1 名工程/制作人员及 2 名手语审核者可安排工作、部分并行估计；工程人时与审核人时分列。外部素材获取及人员排班等待不包含在工作日区间。

## 2. 两条路线的预算

| 项目 | A：复用已有三维姿态 | B：从原视频重建 |
|---|---:|---:|
| 工程/动作修订投入 | 24–48 人时 | 48–96 人时 |
| 手语审核投入（两人合计） | 12–24 人时 | 16–32 人时 |
| 合计人工 | 36–72 人时 | 64–128 人时 |
| 预计经过的工作日 | 5–10 天 | 10–20 天 |
| 自动处理作业 | CPU 作业预留 1–3 h，重型 GPU 作业通常不需要 | GPU 作业预留 4–20 h，另有 CPU 预处理/导出 2–6 h |
| 任务内存预算 | 8–16 GB | 16–24 GB，步骤宜串行以保留系统余量 |
| 显存预算 | 1–4 GB，以预览/显示为主 | 8–14 GB 的目标预算，具体模型及分块需样本实测 |
| 新增工作磁盘预算 | 10–30 GB | 30–80 GB |
| 最终可发布动作/索引 | 约 0.2–1 GB | 约 0.2–1 GB |

内存/显存是分配预算而非已测峰值；当前空闲显存随其他程序变化，不能按 16 GB 全部空闲安排任务。自动作业时间可与部分人工工作并行，不能简单相加为经过工期。CPU/GPU 作业时间不包括人员审核期间电脑持续开机的时间。

磁盘预算包含选择后的素材、中间结果、多个动作版本、调试及相关环境/权重的预留；不包含完整公开数据的下载与全量解压。发布包不含全量源视频、逐帧图像、人体模型和完整审计中间文件。G 盘上次实查约有 513.6 GiB 可用，足以规划上述首批工作盘预算。同日后续[资源核查](../research/csl-reusable-resources-2026-11-06.md)确认 SOKE 三维 ZIP 为 2,886,912,220 B（约 2.69 GiB），但 ZIP64 声明约 248 万个目录项，全量解压的小文件磁盘/IO 开销不能按压缩包大小估算；宜选择序列读取。MVSign 页面显示全量约 1.83 TB，不在本首批预算内。

## 3. 人工投入从哪里来

| 工程工作 | A 人时 | B 人时 |
|---|---:|---:|
| 数据格式/环境/资产接入 | 4–10 | 12–28 |
| 词条索引、批量导入与审核记录工具 | 10–18 | 10–18 |
| 批处理、动作修订与返修 | 6–14 | 20–40 |
| 校验、导出与发布整理 | 4–6 | 6–10 |
| 合计 | 24–48 | 48–96 |

审核预算假设：每位审核者每词 4–8 min（检查两个候选、含义及问题记录），每短语 8–15 min；两人共 `2×(50×[4,8]+20×[8,15])/60 ≈ 12–23.3 人时`，按 12–24 人时预留。重建路线增加一轮问题复查，另预留 4–8 人时，合计 16–32 人时。上述分钟数是本次排期假设，不是行业定额或实测标注效率。

工程人时包含实施、调试、动作修订与验证，不只是生成代码。若只有一人独立完成工程和所有复核，或审核者只能间歇参与，经过时间会延长；手语审核不能由程序测试或反译得分替代。

## 4. 机器时间的依据与不确定性

### 已有本机依据：烘焙/导出

本轮六段共 1138 帧的 Blender 日志时间跨度约 59 s。六个 GLB 合计 9.63 MiB、单条约 1.58–1.67 MiB，角色本体约 1.35 MiB；六份世界矩阵轨合计约 11.75 MiB。日志跨度只覆盖已具备动作的制作/导出阶段，不是整个 Python 驱动流程的完整计时，也不包括从视频重建或人工审核。

仅按帧数线性外推，14,000 帧约需 `59×14000/1138/60 = 12.1 min`；考虑每片段固定开销及额外格式转换/检查，自动处理预留 1–3 h。这个推算不作为未来素材已验证的吞吐承诺。

### 尚未实测：视频重建

本预算假设完整流水线有效速度为 0.5–5 帧/s：

- 单轮 `14000 / fps / 3600`，约 0.8–7.8 h。
- 两轮运行/返工，约 1.6–15.6 h；再留启动、切换和异常余量，预算 4–20 h GPU 作业占用时段。
- 有效速度假设已经用于规划整条重建作业，不代表 GPU 100% 利用率，也不是本机测得的模型 FPS。

[SMPLer-X 官方说明](https://github.com/caizhongang/SMPLer-X#pretrained-models)的 H32 示例约 17.47 FPS，测量条件为 Tesla V100、batch=1。该数字不能直接作为本机 RTX5060 Ti 上完整流程的速度，因此未用于上述本机吞吐计算。

如果要求对全部 14,000 帧做高成本手形/接触迭代优化，另按假设每帧 5–20 s 计算，会额外增加约 **20–80 h 优化作业**。这不是必然开销，也不是本机实测；需通过少量复杂片段确定是否必要。人工精修或重新采集也应另外核算。

当前旧拟合教程与 RTX50 系环境的兼容，以及尚未确认的拟合模型资产，是重建路线的主要排期变量。复用路线的主要变量是公开三维数据是否对应目标词目、可解释并足以通过手形/语言审核。同日后续[资源核查](../research/csl-reusable-resources-2026-11-06.md)已下载 SOKE 小型训练索引并抽查一个参数帧文件，未完成整段转换/播放或语言审核，因此没有新增吞吐实测，也未据此缩短本预算。

## 5. 磁盘与能耗说明

本批若导出全部候选帧图像，假设每帧 JPEG 0.1–0.3 MB，约占 1.4–4.2 GB；这是压缩率假设，分辨率/画面内容会改变体积。逐帧网格、渲染图片和多个调试版本可能显著增加磁盘，按需保留比仅估算最终 GLB 更重要。

整机功耗未测。如仅为规划而假设 GPU 作业期间整机 0.2–0.4 kW，4–20 h 重建作业对应约 0.8–8 kWh；不包括开发和审核时段用电。电费按实际电量与本地电价计算，本次未查询或假定具体费率，也未包含云 GPU/API 或外部人员报价。

## 6. 如何收窄预算

正式批量前先做 3 段代表样本：清晰单手、双手/遮挡、带接触的短句。分别记录格式接入成本、独立帧数、GPU 作业墙钟时间、峰值显存/RAM、自动可读比例和人工修订/审核分钟数，再更新预算。

扩容计算使用实际独立帧数和条目数：

- 重建机时 ≈ 独立帧数 × 轮数 ÷ 有效帧率 ÷ 3600；同一源视频多个词可复用重建结果，避免重复计算。
- 审核人时 ≈ 条目数 × 每条审核分钟 × 审核人数 ÷ 60，再加复查/返修。
- 一次性的环境和词典工具开发不随词数等比例重复；动作修订和语言审核通常随覆盖规模增长。

建议首选 A 路线验证首批，缺失或质量不足的词再走 B。这里的 50 词/20 短语不代表全库 2.55 万余原视频的处理预算，也不包含任意中文连续手语生成。

计算参数及算术核对位于忽略目录 `artifacts/animation-upgrade/resource-estimate/estimate.json`；本轮仅制作估算资料，未启动额外视频拟合或训练。
