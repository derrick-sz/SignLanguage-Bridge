## 3. 可落地的扩库链路

优先复用已标注的真人素材，先做完整短句，减少词间共发音和连接误差：

`原视频 + 已知文本/Gloss → 对齐/裁剪 → 身体、双手、面部观测 → 整段时序三维拟合 → 手形/接触/连续性复核 → 55 关节姿态及 GLB → 版本化动作库`

1. 建立清单，记录语种、数据集、sample ID、split、源视频 SHA、文本/Gloss、句段范围、FPS、签者与来源条件。已有人工标注优先作为标签；模型预测保留为独立候选，不覆盖标签。原视频数量、识别词表大小和可用三维动作数量分别计数。
2. 优先完整句级拟合；需要词级词典时，才用匹配数据域的 S2G 权重和已知 Gloss 做强制对齐并复核边界。句级 Gloss 不自带精确词级时间，现有权重还需实际加载和对齐验证。
3. 补齐并验证视频到三维的推理/优化环境；可考察 SMPLer-X/OSX 与手部拟合器的组合，或 Spoken2Sign 的 SMPLSign-X 路线。固定人体尺度、相机和左右手约定，基于观测置信度识别遮挡；整段优化姿态、速度和加速度，保留承载语义的手形关键帧。
4. 对当前严重回跳片段，先找对应源视频重新拟合；无法对应源视频的片段标记待复核。滤波候选需与原片同时间对照，不能仅提高平滑强度后自动批准。肘部弯曲方向、手部接触和指尖轨迹单独检查。
5. 输出动作参数与可播放 GLB，保留原数据和派生版本。检查关节速度/加速度、骨长、接触、穿模和左右手，再做目标手语使用者的理解审核；导出一致性只是其中一项。
6. 在线采用完整短语检索优先。词级组合还需 Text2Gloss 与经验证的连接器；自由文本生成则另需完整 CSL 生成模型，按 SOKE 等路线验证后接入，不能直接拼汉字或倒用识别器。

建议先以 20 个能匹配原视频、常用且手形可见的完整短句试产，验证重建质量和成本后扩到 100–500 段。此规模是建议，不是本轮已产出数量；训练、三维批量拟合、语言验收均未执行。

## 4. 一手方法来源

- [Uni-Sign 官方实现](https://github.com/ZechengLi19/Uni-Sign)：理解/识别/翻译任务方向；当前本机作用同时由实际 manifest 核对。
- [Spoken2Sign 官方实现](https://github.com/FangyunWei/SLRT/tree/main/Spoken2Sign)：用 TwoStream-SLR 分段、估计三维词典，再做 Text2Gloss、connector 和渲染；方法允许复用已有识别语料，不代表现有权重可直接反转。
- [SOKE 官方实现](https://github.com/2000ZRL/SOKE)：文本到动作 token 与独立的动作 tokenizer/decoder；README 给出 tokenizer 检查点入口，但不能据此假定本机或公开发布的生成器权重完整可用。
