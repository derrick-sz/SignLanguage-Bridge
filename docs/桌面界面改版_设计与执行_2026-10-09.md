# 桌面界面改版：设计与执行

日期：2026-10-09。依据用户截图与“界面太丑、字段不可读，可考虑换框架”的改进要求，优化现有可运行桌面。用户已授权开发和远程同步，沿用原核心边界。

## 设计

采用 PySide6 Qt Widgets，保留 Python 本地摄像头、RecognitionSession 与模型契约。相比继续给 Tk 调整主题，Qt 更适合此次分区布局、字体与高 DPI、图像绘制和可读设置；浏览器前端需要另建本地媒体服务，本轮没有这个必要。

窗口默认1280×820，最小980×720。主区域左侧为来源、等比例视频预览及动作控制；右侧为中葡识别结果和支持词汇。设置独立窗口容纳模型选择、字幕释义加载/重新加载、摄像头设备与技术详情。结果不能被预览尺寸挤出窗口。

- 背景 `#F1F4F8`，面板 `#FFFFFF`，主文字 `#173042`，次文字 `#5C7080`，主操作 `#087F8C`，预览 `#162632`。
- 中文字体 Microsoft YaHei UI，葡语同一字体系统回退 Segoe UI；正文14px，标题25px，中文结果32px、葡语24px。采用留白和明确主操作，避免把所有内容堆成参数表。
- 主标题“手语桥”，副标题“巴西手语识别 / Libras”。用户字段使用“识别模型”“支持的手语词”“中文释义”“Português”。来源只显示文件名或人类可读摄像头名称，完整路径留在详情。
- 模型摘要显示“巴西手语 · N 个词 · 单个动作识别”。词汇只枚举当前模型标签，按同语种字幕词典叠加中葡释义；不将词典额外标签误认为模型能力。
- 标签编号、模型版本、特征格式、词典版本、原始拒识原因、600帧/128MiB限制在详情保留。默认不显示未经校准分数，详情命名“模型匹配分数”，说明其不是识别准确率。
- 中文草案在结果显示“中文释义待核验”。无词典释义时显示待补充，不将item ID冒充葡语词义。拒识清空葡语并提供重试建议。
- 视频按钮“导入视频”“识别视频”“暂停预览/继续预览/重新播放”；摄像头按钮“使用摄像头”“开始录制”“完成并识别”，实际选择设备的索引保留在设置。

## 实施计划

**Goal:** 交付具备真实视频/摄像头操作链路、字段可读的新桌面。

### 约束与复核重点

不改模型权重、media.py字节和RF指标；不宣称连续翻译。Qt镜像只作用于显示副本，QImage必须持有复制后的像素。取消立即清字幕，但底层推理结束前不能再提交任务。每个事件检验request_id/epoch；模型摘要从持久recognizer同步。词典保存后点击重载必须立即影响已显示结果。关闭窗口停止计时器并调用会话关闭，摄像头由捕获线程释放。
