# 视频、摄像头与字幕使用说明

日期：2026-10-09。当前界面使用 PySide6；改版依据：[桌面界面设计与执行](桌面界面改版_设计与执行_2026-10-09.md)，验证结果见[新版验收报告](reports/desktop-redesign-2026-10-09.md)。共享输入与推理接口仍沿用[首版执行方案](视频摄像头输入与字幕_执行方案_2026-10-09.md)。

## 1. 安装与启动

在项目根目录，使用Python 3.12和独立媒体环境：

```powershell
python -m venv .venv-libras
.venv-libras/Scripts/python.exe -m pip install -r requirements-desktop.txt
.venv-libras/Scripts/python.exe -m pip install -e .
.venv-libras/Scripts/python.exe -m slbridge.desktop_cli --help
.venv-libras/Scripts/python.exe -m slbridge.desktop_cli
```

Qt 界面由 `PySide6-Essentials==6.8.3` 提供，与媒体依赖一起由 `requirements-desktop.txt` 安装。帮助命令不打开 GUI 或摄像头。旧命令 `python app/desktop_app.py` 启动同一界面；旧原型另存 `app/legacy_desktop_app.py`。

默认优先使用当前工作目录下试点模型及 `configs/libras_caption_catalog.json`；没有本地词典时使用安装包附带的默认词典。模型不打入安装包或 Git，缺少模型时点击“设置 → 选择识别模型”。模型必须是 `mediapipe225_rgb_v1` 且支持 `clip` 的完整可信本地产物。词典不能让不兼容的 63 维模型变成 Libras 模型。

本地已有试点数据时，模型生成方式见[训练文档](巴西手语训练与验证_2026-10-09.md)。新克隆仓库需自行放入合法取得的数据并先索引，不能直接依赖本机 artifacts 清单：

```powershell
.venv-libras/Scripts/python.exe -m slbridge index --source libras --root "Libras-EQT-UECE (RGB)" --dataset-id libras-eqt-uece-rgb --output artifacts/datasets/libras-rgb/manifest.json
.venv-libras/Scripts/python.exe -m experiments.libras_rf
```

## 2. 界面与设置

左侧是视频／摄像头预览和当前输入的操作；右侧是中文与葡语释义、提示以及支持的手语词。按钮只显示当前输入和任务所需的操作，右上角状态提示反映等待、预览、录制或识别状态。

“设置”包含以下操作：

- **选择识别模型**：选择兼容的模型包目录，等待加载完成。
- **更换释义文件**：选择自己的 JSON 词典；**重新加载**直接读取当前词典路径，供编辑保存后更新字幕。
- **设备序号**：从 0 开始，0 为默认摄像头；更改后在主界面点击“使用摄像头”连接所选设备。
- **详细信息**：查看模型、路径、标签编号、模型分数与错误详情。模型分数未经校准，不能当作正确率承诺。

识别结果区的“详细信息”也可直接打开该页。主字幕使用可读的中葡释义，不显示内部编号或模型分数；缺少释义时提示补充，并在详细信息中保留原标签。

## 3. 视频文件

1. 在“设置”中选择识别模型，等待模型加载完成；主界面显示可读的模型摘要和支持词汇。
2. 点击“导入视频”，选择 MP4/AVI/MOV/MKV，看到等比例预览。
3. 点击“识别视频”；处理期间界面仍可操作，也可点击“取消识别”丢弃本次结果。
4. 完成后显示中文和葡语释义；拒识显示如何重新录制或重试。“清空结果”可清除字幕。
5. “暂停预览”和“继续预览”只控制播放；播放结束后显示“重新播放”。识别始终处理完整文件，不受播放位置影响。

VideoSource在后台先完整解码核对帧数、时间和固定画面尺寸，再回放。全段POS_MSEC都可靠时使用媒体时间，否则整段使用文件自身fps，并记录回退；不混合两种时间线。损坏、少帧、多帧、无可靠时间或超出100万帧上限的文件明确报错。预检不可在原生解码调用中瞬时取消，切源可能等待当前预检退出；界面本身仍可响应。

## 4. 摄像头

1. 点击“使用摄像头”，等待画面打开。默认连接设备 0；也可从预览下方列表选择设备，或在“设置”中调整设备序号后重新连接。列表名称不表示设备已连接。
2. “镜像预览”只影响显示，输入模型的图像不镜像。
3. 点击“开始录制”，完整完成一次动作，然后点击“完成并识别”；录制期间显示已用时间，可点击“取消录制”重新开始。
4. 片段结束后统一采样、提取、预测并显示字幕；模型目前不能边拍边理解连续句子。
5. 点击“关闭摄像头”或关闭窗口，后台捕获线程在当前读取结束后释放设备。识别期间显示“取消识别”，完成后显示“清空结果”。

默认录制最多15秒、600帧、128MiB；帧等比例缩至最大宽640。任一上限超出会清空本次录制并给出错误，不能自动保留动作末尾冒充完整片段。摄像头断开、录制不足两帧、关键点质量不足都有明确恢复提示。设备原生open/read无法安全强制中断，因此关闭窗口不等待它，但停止请求生效后不会再显示旧帧。

## 5. 字幕与词典

configs/libras_caption_catalog.json含12个现有标签的葡语原文和中文释义草案。所有中文当前均标注 `review_status: draft`；界面持续标明中文释义待核验。它是标签查表显示，不是连续文本翻译模型。

编辑并保存词典后，在“设置”中点击“重新加载”，当前字幕立即按新内容重建。需要换到其他文件时点击“更换释义文件”。修改文字不需要重训；更改分类标签或特征契约则需要新的模型包。记录经过真实审核后才改成 `reviewed`，程序不会自动认定审核完成。

缺中文显示“中文释义待补充”，有葡语释义时仍显示葡语；没有可读释义时提示补充，不把内部编号作为字幕。原标签和模型分数可在“详细信息”中查看。词典手语体系不匹配时不套用映射。开始新动作、切源、取消、来源故障会清空上一段字幕；拒识不显示旧成功文本。当前模型概率未经校准，分数不足不等同于可靠的词表外检测。

## 6. 开发接口与测试

- `VideoSource/CameraSource`：同一FramePacket格式，BGR原图、时间戳、帧编号、来源ID；open/read/close由单个后台线程独占。
- `ClipBuffer.finish()`：交付完成的CapturedClip，首帧时间归零。
- `Recognizer.recognize(path)`和`recognize_clip(clip)`：共享模型契约、预测和RecognitionResult；当前模型stream入口仍不可用。
- `RecognitionSession`：一个捕获worker、一个模型worker、有界任务/预览；epoch与request_id隔离迟到结果。
- `CaptionCatalog/caption_from_result`：独立显示词典与字幕，不依赖GUI或模型权重内部结构。

```powershell
.venv-libras/Scripts/python.exe -m pytest -q
```

真实模型的文件／捕获片段一致性检查另需设置 `SLBRIDGE_LIVE_VIDEO` 和 `SLBRIDGE_LIVE_MODEL`，再运行 `tests/test_live.py` 中对应验收测试。桌面控件测试使用 Qt；无显示环境可设置 `QT_QPA_PLATFORM=offscreen`，真实界面验收仍应在有图形桌面的环境执行。当前测试结果见[新版验收报告](reports/desktop-redesign-2026-10-09.md)。

实际界面验收与摄像头连通性探测：

```powershell
.venv-libras/Scripts/python.exe -m experiments.validate_desktop --model artifacts/experiments/libras-rf-pilot-20261009/models/libras-rf-pilot-20261009 --video "Libras-EQT-UECE (RGB)/105_Árvore/INFORMANTE 3/IMG_2971.mp4"
.venv-libras/Scripts/python.exe -m experiments.validate_desktop --model artifacts/experiments/libras-rf-pilot-20261009/models/libras-rf-pilot-20261009 --video "Libras-EQT-UECE (RGB)/105_Árvore/INFORMANTE 3/IMG_2971.mp4" --camera 0
.venv-libras/Scripts/python.exe -m experiments.probe_camera --camera 0
```

`validate_desktop` 实际打开 Qt 窗口、驱动控件、处理视频、验证词典编辑保存重载、清空字幕和 worker 退出。加 `--camera 0` 后继续验证真实摄像头预览、录制和识别任务生命周期；默认录制 2 秒，可用 `--camera-seconds` 调整。结果与文件画面截图默认保存至 `artifacts/desktop-redesign-acceptance-20261009`，也可用 `--output` 指定目录；不保存摄像头图像。

`probe_camera` 仅读取两帧并释放，不保存摄像头图像，15 秒超时终止探测进程。这些检查验证输入与呈现链路，不用于重估模型准确率。首版 Tk 的验证数据保留在[历史报告](reports/video-camera-captions-2026-10-09.md)。

## 7. 本轮边界和后续

已交付文件识别、摄像头片段输入框架、动态双语显示、取消与切源、模型兼容性检查。本轮未改变RF权重；12类试点测试准确率仍为63.89%，不代表真人摄像头表现。真实用户动作、不同设备背景的识别准确率仍需单独采集和评估。

F5仅完成桌面与输入呈现部分；旧collect_data/train_model的采集续录与训练迁移尚待完成。后续先做错误分析与第二backbone对照，再独立实现自动分段、空闲/未知动作评估和真正的流式模型。
