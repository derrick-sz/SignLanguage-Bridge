# Uni-Sign译文分数独立诊断计划

> 执行方式：主代理依次实施；独立审查仅针对诊断脚本与证据，不并行加载模型。

**Goal:** 判断模型自身的beam分数能否补充实时误译风险判断，并测量取分数的时间/显存成本；不预设该办法有效，不以替身或训练拟合代替现场效果。

**Architecture:** 只新增独立实验脚本。固定已有实时train/test各32输入（30正例及2控制）和历史自动句段边界，按相同JPEG90/FrameDecoder/320px共享前端重建133点，单独缓存。另进程只加载一份原Uni-Sign，成对运行原generate与官方output_scores/return_dict路径；临时包装内层mT5.generate，将sequences返回原runtime，其他模型/解码设置不变。只保存有限标量分数和原token，生成全词表score张量不持久化。最后独立EvaluationWorker读取参考，诊断原文严格匹配代理与分数关系。

**Tech Stack:** 现有Python、RTMPose/ORT、Torch、固定Transformers4.40.0，原Uni-Sign源码不修改；标准JSON/NPZ证据。

**Spec:** 本文即有界诊断设计，沿用用户自主调研迭代授权。与直接按已知参考删掉额外句、或把简单活动阈值当意图识别相比，这里先检验无GT的模型信号。只有离线诊断，不提出自动接受/删除阈值，也不接入产品。若无足够区分能力或成本不合适，保留原行为并报告否决证据。

## 约束与风险

- 先核对新输出目录、源manifest/视频SHA/句段边界，旧产物只读。输入/模型输出经GT guard；参考与质量代理只在evaluate阶段读入。
- 重建不是保存的原始pose缓存，须报告新抽点并逐段比较历史译文；不相同的输入不冒充原问题复现。固定句界不是新分句实测，不报告端到端/摄像头延迟或新识别准确率。
- beam score是处理后的累积log分数经过length_penalty归一化，不是P(correct)。记录真实token长度、score步骤数、dtype、beam/penalty；不能把所有步骤数当选中beam长度。
- output_scores会暂存每步所有beam的全词表分数，可能带来显著额外显存/耗时。实际成对测量；不把只读标量的成本当生成全部score的成本。
- 不在服务驻留时再载shadow模型。先读ready/busy/实际生成任务及PID，按项目身份启动器停止两端后顺序抽点/推理，结束后按原profile恢复；不改全局资源策略、不动其他进程或凭据。
- 正常/异常都清除本次临时generate覆盖并释放对象；分阶段产物不假写成功summary。缺正确/错误两类时AUC为空，控制输入不从分母悄悄移除。
- 训练与已见test分别报告；已有test不是盲测，exact代理不等于语义质量。已知额外手势的真实含义仍待真人判断，不能用参考句硬删。
