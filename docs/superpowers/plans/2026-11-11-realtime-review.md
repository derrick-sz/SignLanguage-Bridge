# 实时句末证据与本人核对迭代

用户已授权按项目场景和比赛背景持续自主优化。上一轮吞吐/显式收尾已部署；本轮沿用双模型及输入、FPS、自动分句规则，不重新要求工程设计许可，不改权重、不按GT筛选结果、不提交无关改动。

## 已核验问题

训练样本S000068在首句提交后，原视频约6秒处确实再次出现明显手部动作，非仅重复尾帧或残留词；第二段只有一个新SLRT词“没有”，Uni-Sign却输出“没钱，我出去玩”。自动删除所有再活动会损害真正下一句，当前证据不足以称其非手语。30条训练回放31个句段中只有该段单词证据，其余>=3；30条已见test每句>=3。这些是回溯分析，不证明通用阈值效果或中文语义正确。

## 改动

1. 轻量提示：仅一个词且译文内容字符数显著扩展时附加review_hint，描述“词证据较少、扩写较多”。这是长度启发式，无GT、不需要LLM、不自动拒答/改写/回填；未触发也不代表正确。保留简单“谢谢/你好”等单词表达。
2. 句末事件继续带原始predicted_gloss，网页为每句保存其自身有界word_evidence与提示，不把下一句当前词当上一句证据。
3. 核对界面显示本句词证据及原译文。本人可明确确认，或修改后确认；人工结果/已确认结果不能被迟到机器修订或LLM覆盖。主句显示同步人工修改，历史保留原文与原提示，不把确认状态当语义真值。
4. 若重点核对提示对应单词证据，提供“使用实时词”作为明确的人为修订入口；不静默替换。

## 验证

先写真实engine输出和client交付/确认/迟到修订/词证据绑定回归，观察RED后实现。固定30 train+2控制及30已见test+2控制重放，保留全部样本和原始text/WER分母；原误追加仍在原预测中，只检验提示及人工修复流程，不用提示后剔除输出计算虚高匹配率。独立审查后经身份核验启动器部署，浏览器实际跑出句子、人工确认/修改和证据显示；保留取消与延迟边界。物理摄像头、新签者、人类语义评测和自动判定额外手势意图仍未验收。

研究依据：轻量手语活动检测是单独训练/评估任务（Moryossef等2020，https://arxiv.org/abs/2008.04637），不是位移阈值即可证明语义的接口；本轮不把其DGS性能外推CSL。项目既有中巴场景报告强调限定表达、确认纠错和共同语义审校，具体比赛评分规则未取得。
