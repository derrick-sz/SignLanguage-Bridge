用户已在当前对话确认“进行模型切换”，采用此前建议：完整录制/上传片段由 CSL-Daily Uni-Sign 基础版翻译整句，遵守既有 prod 默认；S2 不自动升级为生产默认。

当前 8879 网关按次协商 8765 的任务及表示，已支持 text 结果；只需让启动器读取本机 profile 的模型别名与设备，并把中文路由绑定现有 Uni-Sign bundle。使用有 Torch/RTMPose/API/RF 依赖的 .conda-env，device=auto，实测必须确认模型与姿态使用 CUDA。Libras 保持独立 RF 路由。旧 profile 缺省字段仍沿用旧参数，避免破坏已有启动入口。

先在 8766 加载同配置并进行真实文件推理；成功后只替换身份核验通过且空闲的 8765 进程。8879 进程和数字人素材复用，不覆盖并行会议页面改动。启动等待可配，重模型配置为 180 秒。校验中文服务确实 ready，不能由另一语种 ready 冒充中文已就绪。

保留原 profile/catalog/脚本副本。新服务不通过加载、实际 GPU 或 HTTP 推理检查时回退原配置。当前页面仍是完整片段识别，模型切换不构成原生流式接入；实时增量建议另走本地 SLRTBackend.new_stream，输出 Gloss，非手语到完整句子的流式翻译。

验收：启动参数来自 profile；真实健康状态和协商均为 Uni-Sign/text；同一文件通过 8879 得到与直连 8765 相同的原始句子；WebM 录制格式适配；Libras 路由与人物/词库身份保持；启动器再次运行能复用新识别与原产品进程；错误路由 profile 不停止服务。物理摄像头、用户“我想睡觉”录制复现、识别语义质量、实时字幕延迟和 LLM 融合仍需分别验收。
