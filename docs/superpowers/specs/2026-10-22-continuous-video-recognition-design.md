# 连续视频流滚动识别

## 用户方向与诊断

用户报告中／巴手语均卡顿，并明确提出“实时处理视频流进行识别”。本次按连续取帧、滚动窗口、后台识别、持续更新当前结果实施，不再把停顿作为推理的前置条件。沿用现有完整片段模型，不能宣称已得到原生因果流式模型或连续句子翻译。

已复现：连续运动 4 秒提交 0 次，随后必须等待约 0.67 秒才提交。中文完整 8.2 秒视频 CPU 为 6.33–6.67 秒，GPU 为 2.12–2.36 秒，两份完整 logits／解码对照通过。Libras 已采集片段处理 1.10–1.95 秒，其中 RF 约 5 毫秒，成本主要在关键点提取。

## 行为

- 主界面新增“连续识别视频流（无需停顿）”；与旧“停顿后追加字幕”互斥。保留手动录制、导入完整视频、语言热切换和已提交字幕历史。
- 连续识别显示“当前窗口结果，随画面更新”，不将重叠窗口伪装成已确认词句，也不按窗口重复写入正式字幕历史。当前结果必须在关闭模式、换源、模型切换、取消、清空和质量丢失时失效。
- 摄像头与视频回放均可输入；采集、活动观察、模型工作在各自现有线程。使用至少 1.2 秒、最多 2.4 秒的滚动窗口，目标提交间隔 0.5 秒，实际刷新由模型吞吐量决定。后台仅一个模型任务，无待处理窗口队列；空闲时从最新缓冲重新取窗口。
- 帧缓冲时间／帧数／字节有界，默认最大宽度 640、180 帧、96 MiB；在滚动窗口内淘汰旧帧是显式输入范围，不改变模型保存的预处理协议。每个窗口仍经原有 captured_clip 接口、质量校验与 clip 模式推理。
- 仅当最近真实活动观察显示手可见且质量合格时采集候选窗口；丢失质量立即清空当前候选、取消其结果交付，恢复后重新积累窗口。没有手时不显示闭集分类器猜测的词。
- 结果同时受 source epoch、模式版本、模型 generation 和窗口时间约束；超过 3 秒的结果丢弃，界面显示刷新／过期状态。原生调用无法强制终止，期间视频预览继续。
- 停止连续识别后，待原生任务返回才能手动识别或切换模型。切换成功后用户可再次开启连续识别。

## GPU 桌面

为既有独立 GPU 环境安装仓库锁定的桌面／MediaPipe 依赖，不改 CPU 环境与模型权重，保留 ORT GPU。提供启动脚本选择依赖齐全的 GPU 环境，缺失时明确使用 CPU；实际 provider 需要通过识别响应读回，不根据硬件名称猜测。

## 验证与范围

RED→GREEN：持续运动且没有停顿也调用模型／更新当前结果；慢模型只消费最新窗口；帧缓冲有界；关闭、取消、换源、换模型、质量丢失与过期均不显示迟到结果；不污染字幕历史；旧自动／手动流程保留。

使用真实中文和 Libras 视频，以实时回放和真实模型测首个候选、刷新间隔、窗口结束至结果、丢弃与 provider。摄像头有帧才可报告实机通过；先前设备读取失败不能用视频回放代替。候选准确率、未知动作拒识和连续整句翻译不由机制测试证明。既有中文长字幕裁切只记录，不扩大成全界面布局改造。
