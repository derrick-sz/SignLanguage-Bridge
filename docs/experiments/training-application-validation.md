# 训练样本的应用识别验证

用户目标是先利用已有语料覆盖可用场景，不要求研究型的新签者泛化。本轮检查真实训练视频在现有产品链路中的还原能力，区分训练回放、用户模仿和日常场景覆盖。

## 固定输入与协议

- 从既有657条Uni-Sign训练拟合样本中取视频/官方姿态都存在的短句，逐一核对官方 `csl-daily.train`，并与dev/test无交集。模型未训练或微调，权重与当前服务保持不变。
- 按作者姿态pkl的 `[start,end)` 取原视频，核对原视频帧数与姿态总帧数一致；缩为512正方形MP4V、保留原FPS。选择规则为长度≤200帧、按样本ID排序后签者轮询，固定30条/8签者，不按模型输出、历史匹配情况或词数挑选。符合时长条件112/657，结果范围仅短句。
- 目标句/Gloss只保存在eval目录。推理只读视频，LLM关闭，不将目标练习句回填给模型。
- A：同样本、同SHA权重的官方姿态历史预测，仅作为imported参照，不冒称本轮重跑。
- B：新派生视频→原产品上传接口→Uni-Sign整句输出，30条真实请求。
- C：与B同一视频→原FPS JPEG/WS→SLRT增量词+Uni-Sign句末，显式增加1.2秒末帧，30条真实回放。
- 黑帧和静止人物各一条，同时跑B/C，不计入正例指标。
- 两个裁剪诊断样本按“旧HRNet近似裁剪长度与作者区间相差≥100帧”的条件预先固定；分别跑作者区间/旧区间的视频上传，共4次请求。诊断样本不混入主30条。

## 待检验的解释

1. 如果旧裁剪截掉有效动作，同一ID仅换成作者区间，应改善视频输出；保持其他参数一致。
2. 如果本地姿态输入造成明显损失，作者区间的视频输出仍会明显低于同ID官方姿态参照；此差异含输入分辨率/重编码等整条前端，不能只归因于某一个姿态网络。
3. 如果实时分句/调度产生额外损失，C应低于B；按帧数、分句理由、重置、拒答和原始事件定位。

## 输出与验收

产物：`artifacts/train-application-validation-v1/`。selection/manifest在模型调用前冻结；脚本、视频、姿态与官方划分有SHA。每条失败/空输出均保留，指标沿用P1 canonical评测器。主要观察规范化整句匹配、逐条原文对照及SLRT词WER；BLEU和字符相似度作辅助，不称为产品准确率。

运行脚本 `scripts/validate_training_application.py prepare|run|evaluate`。准备时已有3项定向测试覆盖独立于输入顺序的选样、真实视频的左闭右开裁剪/FPS与作废词的评测处理。不会重启当前服务或加载另一份大模型。

本轮不以训练视频回放推定模仿动作、新签者或“多数真实需求”已经通过；先给出可用/失败表达及链路损失，再据此确定应用场景。

## 运行现场补充

v1交替跑上传/实时后发现实时过载，已主动中止并保留全部结果：4次裁剪探针+9条训练视频，上传无错误、9条规范化整句均匹配；9条实时均overload，不能计算完整主词WER。独立重跑训练单例和上次已通过的测试单例，也均overload（静止人物同样失败、黑帧通过）。故该故障不能解释成训练样本识别质量差。

源码逐项SHA与最终v5冻结文件完全一致，配置未变；旧服务已运行22.8小时。保存 `slow-runtime-before-restart.json`，通过既有身份核验启动器Stop/Start同配置服务，没有任意结束其他进程。重建后旧测试单例+黑/静止全部通过，静止人物姿态均值约14.49ms/帧。长期闲置/运行后的变慢原因仍待定位，不能把重建恢复写成已修复根因。

v2复用v1全部已冻结的视频字节、样本顺序和标签，只新建结果目录和服务进程；参见 `artifacts/train-application-validation-v2/manifest.json` 的来源SHA。不会按v1识别结果重新选样或删掉失败条目。两条裁剪探针的新旧区间目前均输出同一句，尚无该变量造成误识别的证据。
