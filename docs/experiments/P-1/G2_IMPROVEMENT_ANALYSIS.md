# G2 改进分析：从"润色改写"转向"gloss 造句"（2026-10-27）

> 状态：**UPDATED**（方向 1 已实测：部分成立——LLM 造句显著优于 B0 但未超过 A；瓶颈在 SLRT gloss 的 WER 30%）
> 对应：RQ3（融合能否提高译文质量）、G2 Gate 的替代路线

## 1. 根因：为什么当前融合方案失败

### 1.1 证据链

| 证据 | 数字 | 含义 |
|---|---|---|
| Uni-Sign 视频（A）BLEU | 24.82 | 基座本身不高 |
| A 的人评严重错误率 | **80.8%** | 八成输入本身有语义错误 |
| A 的动作槽位错误率 | **57.5%** | 最弱的是内容词（动作/对象），不是句法 |
| A 的流畅度 | 4.62 / 5 | 句子"看起来"很通顺——**通顺但错误** |
| SLRT Gloss（B0）动作槽位错误率 | **45.0%** | Gloss 在内容词上比 A 更可靠 |
| B0 的流畅度 | **2.07 / 5** | 但 Gloss 完全不成句 |
| LLM 融合 C/D/E BLEU | 全部 < A | LLM 无法在"通顺但错"的输入上做出正确的事实判断 |
| D−C（Gloss 增值） | 不显著（两版 prompt） | 给 LLM 加 Gloss 证据并不能让它改对 |

### 1.2 结论

**当前方案的根本错误：把 LLM 当"事实仲裁者"用。** 我们给 LLM 一个通顺但常错的句子（A），加上一堆可能冲突的证据（gloss），然后指望它判断"哪个是对的"——这正是 LLM 最不擅长的事。

**LLM 真正擅长的是语言组织。** 如果我们给它**正确的事实**（gloss 内容词准确率更高）并只要求它**把这些词组成自然句子**，那就在用它做强项。

## 2. 改进方向（按收益/成本排序）

### 方向 1：B0 → LLM（"gloss 造句"，已实测，2026-10-27）

**实测结果（50 条 pilot，wb-proxy/deepseek-v4.1-flash，temperature=0，max_tokens=2048）**：

| 组 | n | BLEU-4 | chrF | char edit |
|---|---:|---:|---:|---:|
| A（Uni-Sign 译文） | 50 | **31.2308** | 27.1849 | 0.4831 |
| B0（gloss 无空格 join） | 50 | 12.5914 | 13.9142 | 0.3550 |
| **F（gloss 空格→LLM 造句）** | 43 | **19.4749** | 18.2871 | 0.4009 |

配对 signer bootstrap：**F−B0 +7.072 [3.645, 10.700]**（显著更好）；**F−A −12.691 [−18.341, −6.345]**（显著更差）。

**结论**：
- ✅ LLM 的语言组织能力得到验证：gloss → LLM 造句比确定性 join 好 7 BLEU
- ❌ 但追不上 A：**瓶颈不在 LLM 造句，而在 SLRT gloss 的 WER 30%**（30% 的 gloss 词本身是错的，LLM 只能"通顺地组织错误事实"）
- 15/43 样本 F 的编辑相似度优于 A（不是全面溃败）；BLEU 对近义措辞惩罚偏严
- **如果 SLRT WER 能降到 15-20%，F 可能超过 A**（推算：F ≈ A − 12 + 7×(30−WER)/30 ≈ A @ WER ~15%）

**失败模式**：7/50 调用因 2048 截断返回空文本（推理模型内部 token 耗尽预算；需 4096）；gloss 保留率 mean 0.858。

详见 `report_group_f.md`（含 8 条 GT/A/B0/F 并排示例、失败模式分析、分词对照）。

**思路**：把 SLRT 识别出的 gloss 词序直接交给 LLM，让它组成一句自然中文。不给 Uni-Sign 译文（避免 LLM 被通顺但错误的 A 带偏），不让 LLM 做事实判断。

**为什么可能有效**：
- Gloss 内容词错误率 45%/34%（动作/对象）< A 的 57.5%/43.3% → 输入事实更准
- LLM 的强项就是把不通顺的文本变成通顺句 → 正好匹配
- 人评 B0 平均分 1.93 > A 的 1.50 → 语义上 gloss 更接近真值
- 如果 LLM 能把 B0 的流畅度从 2.07 提到 ~4，同时保持内容词准确率 → 可能超过 A

**风险**：
- Gloss 可能遗漏虚词/句法标记，LLM 可能需要"猜"句法关系
- Gloss 的词序可能不符合中文语序
- 30% WER 意味着有些 gloss 词本身是错的

**实验设计（组 F）**：
- 输入：SLRT gloss 词序（空格分隔的词列）
- Prompt v3_f：`【任务】把下面这些手语识别出的词汇组成一句自然流畅的简体中文句子。保留所有词汇的意思，不得添加、删除或改变任何词汇的内容。`
- temperature=0，max_tokens=2048
- 50 条 pilot 样本，同 A/B0 基准
- 评测：BLEU/chrF/edit + 与 A/B0 配对 signer bootstrap

### 方向 2：确定性槽位修补（无 LLM，零成本）

**思路**：拿 A 的句子做底（流畅），用 E06 RuleJudge 检测槽位冲突，只在 SLRT 高置信时替换该槽位的词。

**与方向 1 的区别**：方向 1 是"gloss 造句"（抛弃 A），方向 2 是"A 打补丁"（保留 A 的句法，只换错词）。

**适用场景**：方向 1 如果 LLM 造句的 BLEU 不高（LLM 可能补出错误句法），方向 2 可能更稳。

### 方向 3：A2 作为默认（已证明，零成本）

人评 +0.158（CI 不含 0）、BLEU +0.77：**有官方 pose 时直接用 A2，不要用视频路径**。这只改部署策略，不需要新实验。

### 方向 4：S2T 独立基线（高投入，独立失败模式）

SingleStream-S2T（video→sentence）是另一个翻译模型，失败模式与 Uni-Sign 不同。如果解锁，可以做模型级 ensemble（而非文本级融合）。但需要建环境 + 取资产（见 `s2t_feasibility.md`）。

### 方向 5：SLRT 帧缓存合入生产（纯工程收益）

已验证等价（WER 不变、e2e −18.4%）。落到 `SLRTRuntime`/`SLRTStream` 并更新 protocol。

## 3. 与已有结论的关系

- **不推翻 G2 FAIL**：那是"LLM 仲裁式融合"的结论（A 做底 + LLM 判断对错），证据充分。
- **开辟新假设**：如果"gloss 造句"（B0 做底 + LLM 只管通顺）有效，那说明**问题不在融合本身，而在融合的角色分配**。
- **与 ADR-P1-002 不冲突**：该 ADR 说"生产默认单模型"——方向 1/2 仍是非默认的实验分支。
