**理解边界**：官方说明存在模型或 online demo，并不等于本地 checkpoint 已下载、预处理与当前 CSL 数据一致、实时首稳延迟满足需求。P-1 应实际验证这些条件。

## 3. 最值得优先回答的技术调研问题

1. **Uni-Sign**：当前视频预测实际调用的是哪个 checkpoint、哪个视觉帧采样器？release pose 由哪个工具生成？生成分数/候选 beam 是否可导出？官方 online demo 是实时采集还是“读取视频路径后的在线处理”？
2. **SLRT TwoStream-SLR**：HRNet 关键点的原始尺度、输入点顺序、帧裁剪、视频开始位置对齐机制是什么？当前 local alignment 相对于官方输入是否引入不可接受的性能偏差？
3. **SLRT TwoStream-SLT**：可获取的 CSL-Daily 权重是否包含可直接复现的翻译推理配置？它和现有 Gloss 识别 checkpoint 是否适合同一个视觉前处理？
4. **SLRT Online**：它是否可以拿现有 TwoStream-SLR checkpoint 直接替换？还是需要独立构建词典、训练孤立词识别器？输出 partial 的时间条件是什么？
5. **Jev**：输入仅文本或 JSON，适合辅助升级策略；其 Choice/Score/Noul 输出置信度对中文、Gloss/葡语是否校准？API 实际延迟和费用如何？
6. **部署与资源**：目标 GPU 的 RAM/VRAM、视频解码速度、CUDA 版本、Docker 隔离、worker queue 深度决定并行是否有意义。
7. **数据与授权**：CSL-Daily 源视频、关键点、官方权重与开源代码是否可在目前使用场景分发、缓存或用于商业化展示？

## 4. 后续 Libras 的研究边界

1086 条测试全部是 CSL；无法凭它验证自动区分 CSL/Libras，也无法验证跨语言模型泛化。Libras 阶段必须单独建立具有 signer、采集场景、手语体系真实标签的视频资源和评价标准。`SignSystemRouter` 接口可提前保留 `Unknown`，但路由能力标记为 `UNTRAINED`/`NOT_VALIDATED`，不能伪装已经实现。
