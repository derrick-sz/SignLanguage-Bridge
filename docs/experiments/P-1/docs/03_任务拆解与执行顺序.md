## 开发规范

- 主分支不直接提交；每个实验模块有 `test_*.py` 与最小 mock 输入，并以 schema 校验为底线。
- 对外 API 与 V3.0 一致，不在 P-1 内定义与 V3.0 冲突的字段。新的 metric/provenance 字段应向后兼容且允许 `null`。
- 输入数据、临时权重路径通过配置，不把用户 Windows/远程 Docker 路径固化在源码中。
- 使用 dry-run/历史 JSONL 可以先测试日志、融合流程，**历史回放不算模型前向实测**。
- 若某任务无法完成，应留下 `blocker.md`、最小复现、依赖/权重缺失及建议替代分支。
