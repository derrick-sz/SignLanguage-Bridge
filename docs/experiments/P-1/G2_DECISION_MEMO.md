# G2 决策备忘录：双模型 + LLM 融合是否进入后端主链路

> 决策人：Lead（依据实测证据撰写；独立模型评审尝试失败，见 §7）
> 日期：2026-10-27 · 状态：**ACCEPTED（不进入主链路）**
> 对应：RQ3（Gloss→Text/SLT 与双模型融合能否提高译文质量）、RQ7（Jev/LLM 能否纠错而不覆盖正确答案）；Gate G2；ADR-P1-010
> 证据边界：**50 条 Pilot-50 探索批，`retrospective_seen`，不是最终盲测**；两组 prompt（v1、v2）、单端点（wb-proxy）单模型（deepseek-v4.1-flash）、无人评。

## 1. 决策问题与验收三问

1. **翻译质量是否确实提高？**（canonical BLEU-4/chrF + signer 聚类 bootstrap，禁止凭个案）
2. **是否引入新的关键事实错误？**（人物/否定/数字/时间/动作/对象六槽位盲评，统计纠对/改错）
3. **增加的计算成本是否值得？**（LLM 调用数/tokens/P50-P95 vs 单模型基线）

预判据：`D vs C` 验证 Gloss 新增价值；`E vs D` 验证证据约束。若 D/C/E 不能稳定优于 A，则不启用融合。

触发信号 = E06 RuleJudge 对 A vs SLRT Gloss 的槽位冲突：**触发率 28.00%（14/50）**（person 8 / negation 6 / numbers 3 / question 1）。触发子集上 E_v2（21.96 BLEU）优于 E_v1（16.63），级联采用 **E_v2**（两版均报告）。

| 策略 | BLEU-4 | ΔBLEU vs A [95% CI] | LLM 调用/占比 | tokens | P50 / P95 |

### 2.4 成本（v2 批实测，含失败调用消耗）

- tokens：**125,976**（prompt 57,150 / completion 68,826）；分组 C 25.7k / D 38.9k / E 48.7k（成功调用的 usage）。
- 延迟（HTTP 端到端，严格串行）：per-call **P50 3.16 s / P95 10.82 s**（mean 4.23 / max 15.16）；C P50 2.04 s、D 3.01 s、E 4.48 s。
- 对照单模型：Uni-Sign pose 模型侧 P50 277.6 ms；视频端到端 P50 2,690.4 ms（E04 warm，50 条 pilot 上 E01 为 3.625 s）。
- 失败：v2 批 150 次调用失败 5（全 E 组，`finish_reason=length` 于 2048 截断；非网络错误；未重跑）。**E 组若要继续需单独 4096 预算。**

## 3. 三问逐条回答

1. **质量是否提高？——否。** 两版 prompt 下 C/D/E 的 BLEU 点估计均低于 A（C−A 两版均显著为负）；D−C、E−D 均不显著；edit 相似度中性。唯一亮点 v1 的 E−C edit 在 v2 未复现。
2. **是否引入新的关键事实错误？——未验证（缺人评）。** 六槽位盲评（Round-1 包：120 样本 × A/A2/B0、盲序、双评审协议、校验脚本）**等待用户本人回填**；E06 槽位规则只是代理信号，不能替代人评。抽查示例可见 LLM 会改掉正确事实、补全证据外内容（`report_real_50.md` §5）。
3. **成本是否值得？——不值得。** 级联省 72% 预算但质量 ΔBLEU −0.48（CI 含 0、点估计为负）；全调 LLM 显著更差；额外 P50/P95 秒级延迟对实时语义不可接受。

## 4. 决策

- **G2 结论：FAIL（融合无质量增益证据）**。按 ADR-P1-008 与 Gate G2 的预先约定：**融合不进主链路；保留可插拔接口与离线评测管线（`experiments/p1/e02/llm_fusion/`），生产默认单模型（Uni-Sign 视频或官方 pose 路径）**。
- **不扩到 1086**：在当前证据下只会更精确地测量同一个"无增益"结论。
- SLRT 的 Gloss 价值**未被否定**：B（G2T/SLT）BLOCKED、B0 只是 join 基线；获得 CSL-Daily G2T 权重后应重做 B 与 D vs C。
- Jev/LLM 仲裁（RQ7）**保持 BLOCKED**：无端点级证据支持纠错能力。

## 5. 重启条件（若未来要再评估融合）

1. 固定可复现的 LLM 端点 + 模型版本 + prompt 版本（管线与记录纪律已建立）；
2. prompt 在**开发集**上系统调优（不在同一 50 条上反复试错后宣称提升）；
3. 新的独立测试集（未见 signer/环境）且无 GT 泄漏；
4. Round-1 人工评审回填，证明 E/C 类候选在关键事实槽位**纠对 > 改错**；
5. 明确成本上限（tokens/延迟）并证明质量增益 CI 不含 0。

替代路线（优先级）：① B（SLRT G2T/SLT，等外部权重）；② **确定性选择性后处理融合**（仅 RuleJudge 冲突时用 Gloss 修正，不依赖 LLM，可先规则版+人评）；③ 人工评审回填。

## 6. 风险与边界

- 50 条探索批、`retrospective_seen`；不能外推到 1086 或新 signer。
- 单端点单模型（deepseek-v4.1-flash）；v1 首轮 `max_tokens=256` 事故已隔离（73/150 空 completion，未进对比表）；v2 批 5/150 失败已披露。
- v1→v2 是在已见数据上的 prompt 迭代，**不得声称泛化提升**。
- 6 槽位人评未做："关键事实错误"维度是**未验证**，不是通过。
- 本备忘录不评测其他 LLM；换模型需重跑同协议并记录。
