# P-1 / G2 实验问题总结（2026-10-27）

> 来源：E00–E06、G2 真实 LLM 实验（v1/v2 prompt、组 F、槽位修补）、阶段 4 优化、Round-1 人评、独立审计。
> 目的：把"实验暴露出来的问题"按层面归类，区分**模型能力问题 / 数据与评测问题 / 方法学问题 / 工程问题 / 外部依赖问题**，并给出可执行的对策。
> 纪律：每条都有证据来源；不把"未验证"写成"已失败"。

## 0. 一句话结论

**当前系统的主要瓶颈不是"融合策略不够聪明"，而是两个模型各自的质量上限 + 评测数据不完整 + 输出端融合无法创造输入端不存在的信息。** 7 种文本级融合全部负结果，进一步做融合的边际收益极低；真改进必须来自模型内部融合（RGB+pose）、上游识别质量或独立模型。

## 1. 模型能力问题（最根本）

| # | 问题 | 证据 | 影响 | 对策 |
|---|---|---|---|---|
| 1.1 | **Uni-Sign 事实错误率高** | Round-1 人评：严重语义错误 **80.8%**、动作槽位错 57.5%、对象错 43.3%（120 样本） | 八成语义不可靠；任何"润色"都在错误基础上改 | 接受现状或换更强的模型/权重；不能靠后处理补救 |
| 1.2 | **SLRT gloss WER 30.18%** | E02/E03 实测（vs 论文 27.4%，差 2.8pp） | 三成 gloss 词本身错 → 用它修正 A 会传递错误（槽位修补 object 槽位 0 改善/9 恶化） | 提升 SLRT 输入协议（官方句帧缺失，见 5.2）或换前端/重训 |
| 1.3 | **Uni-Sign 无分数输出** | `TextPrediction(score=None)`；历史 JSONL 无 logprob | 无法做置信度、无法做风险路由、无法做选择性融合 | 增加 `output_scores` 重跑（需改 runtime + 重跑 1086） |
| 1.4 | **SLRT 分数未校准** | ECE 0.304（raw）→ OOF Platt 后 0.026 | raw score 不能当概率；只能排序 | 按 signer 分组校准；用作排序而非阈值 |
| 1.5 | **Uni-Sign 无原生 Partial** | 对称时间卷积 ±6 帧 + 双向 mT5 encoder；E05 前缀探针 mean 90%/median 100% | 不能做实时字幕；只能整句识别 | 实时场景另找因果模型 |
| 1.6 | **SLRT 不能实时** | replay RTF 2.23–2.58、7.5–7.9 窗/秒（30fps 需 ~30） | 实时字幕不可用 | 提升吞吐 2–3× 或降低采集 FPS；帧缓存已 −15.9% 但仍不够 |
| 1.7 | **A/A2 高度相关** | 507/1086（46.7%）文本完全相同 | 两路互补空间天然小（oracle 仅 +1.78 BLEU） | 不要指望 A/A2 级联；真正的互补需独立模型（S2T） |

## 2. 数据与评测问题

| # | 问题 | 证据 | 影响 | 对策 |
|---|---|---|---|---|
| 2.1 | **测试集不完整** | 本地 test 覆盖 **1086/1176**，缺 90 条（偏长句，平均 159.6 帧） | 评测偏容易；长句能力被低估 | 补齐 90 条视频；或明确声明"1086 子集" |
| 2.2 | **retrospective_seen 不是盲测** | 1086 条被反复分析（阈值选择、案例挑选） | 任何"提升"不能当泛化证据 | 新独立数据/新 signer；论文结论需盲测 |
| 2.3 | **参考文本口径陷阱** | 上游半角 vs 官方全角，同一预测差 **2.8–3.1 BLEU** | 混用会导致错误的"提升/退化"结论（已踩过：R17 −3.82 是口径错误） | 冻结 `ref_sentence_upstream`；文档+代码双重标注 |
| 2.4 | **Pilot-50 子集偏容易** | pilot BLEU 31.2 vs 全量 24.8（差 6.4） | 不能拿 pilot 数字比论文/全量 | 只用 pilot 做诊断/对照，不做绝对质量声明 |
| 2.5 | **BLEU 对近义改写惩罚大** | 组 F 示例 6/7 语义接近 GT 但分低 | 可能低估 LLM 造句的真实价值 | 必须配人评；BLEU 只作参考 |
| 2.6 | **人评不是独立双人盲评** | Round-1 由 Codex-AI 填写 + 用户确认；复核列与首评完全一致（agreement 1.0） | 不能声称"人工评审发现" | 明确写"AI 辅助评审（用户确认）"；关键结论需真人双评 |

## 3. 方法学问题（我们自己的实验设计）

| # | 问题 | 证据 | 影响 | 对策 |
|---|---|---|---|---|
| 3.1 | **同一 50 条上反复迭代 prompt** | v1→v2 在同一 pilot-50 上调 prompt，C 提升 +2.27 | **过拟合风险**：v2 的提升部分来自"针对这批样本" | 停在同一集上迭代；新 prompt 必须换开发集/新样本 |
| 3.2 | **样本量小、CI 宽** | 50 条 signer bootstrap CI 常跨 ±5 BLEU | 难以判定小效应（如 E−D +1.62 n.s.） | 关键对照扩到 200–1086；或用配对设计提效率 |
| 3.3 | **组 F 首跑输入错误** | 首跑用 B0 原文（无空格 join），与"空格分隔词列"规格不符 | 已重跑纠正；但暴露"输入渲染未预先冻结"问题 | 输入格式纳入 protocol 版本；首跑前做 stub 快照 |
| 3.4 | **max_tokens 预算不足** | v1 首轮 73/150 空补全（256）；F 组 7/50 截断（2048） | 失败集中的样本更难 → 指标偏高（选择性偏差） | 4096 + 失败重试；失败样本单独报告 |
| 3.5 | **无 GT 选择器时融合不可部署** | 所有融合都靠 GT 才能选最优（oracle）；无 GT 信号时 A/A2 47% 相同 | "融合上限"只是理论值 | 只报告 oracle 为上限，不当作可部署收益 |
| 3.6 | **阈值/规则在同一集上选择** | 槽位修补阈值 0.4/0.5/0.6 在同 50 条上比 | 同样过拟合风险 | 阈值必须在开发集选、测试集只跑一次 |

## 4. 工程/环境问题

| # | 问题 | 证据 | 影响 | 对策 |
|---|---|---|---|---|
| 4.1 | **延迟从未纳入决策** | G2 验收第三问只报了 token 与单次 P50/P95，未算管线总延迟（用户指出） | 可能选错架构（如选 8.5s 的方案做实时） | 每次比较都带端到端延迟；按场景（实时/批处理/离线）分别决策 |
| 4.2 | **SLRT 单条 5.5–6.5 s 太慢** | E04 6,497 ms；帧缓存后 5,464 ms | 任何含 SLRT 的组合 ≥5.5s，实时不可用 | 需 2–3× 吞吐提升或降低 FPS |
| 4.3 | **Uni-Sign 视频路径 pose 占 80%** | E04：2,690 ms 中 pose 2,156 ms | 视频路径优化空间在姿态前端 | `pose_sample_only` 在 CSL-Daily 近乎 no-op（仅 1.1% 片段 >256 帧） |
| 4.4 | **`pose_detect_stride=5` 域依赖** | CSL-Daily −1.69 BLEU / Δedit −0.0205（他域曾"无显著差异"） | 不能跨域外推加速开关 | 每域做配对质量门槛（Δedit ≥ −0.005 且 CI 下界 > −0.01） |
| 4.5 | **双环境依赖割裂** | `.conda-env`：无 pydantic/FastAPI；`.venv-libras`：无 torch/yaml | API 测试与 ML 测试不能在同一环境跑 | 记录双环境矩阵；CI 分两段跑 |
| 4.6 | **GPU 显存/宿主内存压力** | cold video 2 次 CUDA OOM（GPU 空闲 >13GB，committed 55.7/65.2GB） | 偶发假失败，易误判模型问题 | 重试策略 + 记录 spawn_attempts；并行前设 RAM 门 |
| 4.7 | **历史 sparse-checkout 坑** | cone 只含 `/configs/`，导致 35 个模块缺失、`git add` 被拒 | 复现风险（已修复并记录） | 禁用；FREEZE.json 记录根因 |
| 4.8 | **报告数字与底层 metrics 曾不一致** | E04 warm P50 报告 276 vs metrics 277.6（审计发现 4 项） | 降低可审计性 | 机械审计脚本（14/14）+ 独立审计（4 项已修） |

## 6. 按严重度排序的"必须解决"

| 级别 | 问题 | 为什么最优先 |
|---|---|---|
| **P0** | 1.1 Uni-Sign 事实错误 80.8% | 决定产品可用性；任何上层优化都受它限制 |
| **P0** | 2.2 retrospective_seen + 2.1 缺 90 条 | 没有独立盲测，所有结论都不能对外声称 |
| **P0** | 1.2 SLRT WER 30% + 5.2 官方帧缺失 | 堵死 gloss 路线；且无法复现论文 |
| **P1** | 1.3 Uni-Sign 无分数 | 堵死所有"选择性/风险路由"方案 |
| **P1** | 4.1/4.2 延迟 | 决定能否做实时产品 |
| **P1** | 3.1/3.6 同集迭代 | 影响所有实验结论的可信度 |
| **P2** | 5.1 G2T 缺失、5.5 Libras | 长期路线，短期不必等 |

## 7. 建议的下一步（按性价比）

1. **Uni-Sign RGB+pose 接入**（权重已在本地，论文 +0.75 BLEU）——唯一未试的**模型内部融合**，task-28 进行中
2. **SLRT 对齐算法改进**（不改模型，只改裁剪）——可能收回 1–2pp WER，让 gloss 路线重新可用
3. **补 90 条 test 视频 + 新独立 signer 集**——解除 2.1/2.2，让结论可对外
4. **Uni-Sign 输出 scores**（改 runtime + 重跑）——解锁置信度/风险路由
5. **停做文本级融合**——7 种方式已充分证伪
