# 模型运行 API 与 ONNX：设计与执行

本次按用户已同意的核心分层和新增 API、GPU/ONNX 要求实施。目标是统一调用契约与安全模型替换，保留现有 Libras RF 模型；不宣称已有训练好的 TCN、连续翻译模型或复杂模型时延保证。

## 调用边界

桌面和 HTTP 传输层共用 `ModelManager`。模型包决定 InputSpec、标签、阈值和算法适配器；运行配置决定设备、线程数及 CUDA 内存 arena 上限。模型包完整性和冻结数据契约在反序列化前检查，旧 RF 包保持可读。

HTTP v1 输入采用上传单个完整视频或兼容的 NPY/NPZ 片段，外加 request_id、可选 representation_id/sign_language 声明。服务不接受客户端传入服务器路径或远程 URL。摄像头在客户端完成片段录制，再上传；连续流不伪装成 clip 接口。

统一响应包含 schema_version、request_id、model_generation、RecognitionResult、实际执行 provider 信息和预处理/模型/总耗时。recognized/rejected 是正常业务结果；非法输入、忙碌、模型不可用是结构化错误。分数保留未校准概率语义。

## 模型运行生命周期

第一版采取暂停新识别的安全切换，不要求双模型并行服务。已有任务运行时拒绝切换；候选加载/预热期间拒绝新推理，模型包成功校验并通过真实后端调用后才提交新 generation。失败保持旧模型；保留一个旧实例供显式回退。最多保留两个模型实例，新准备前释放更旧的回退实例。推理容量为一个，忙碌请求立即返回，无无界队列。

桌面录制期间禁止切换，取消或来源变化使候选结果失效并释放；任务结果仍经过 request_id/epoch 过滤。关闭不强行中断 native 调用，调用结束后释放模型。

## 算法与 ONNX

注册 RF 和真实 ONNX classification 后端，不添加空 backbone。ONNX 首批支持 NC 统计特征、NTC 关键点序列及可选 mask，输出稠密概率或 logits。图的输入名、布局、类型、形状、输出和类别顺序均由模型包声明与加载检查；不同 backbone 的完整预处理契约不得混用。

`cpu` 明确使用 CPU；`cuda` 要求 CUDA provider 实际初始化成功且禁止运行时静默回退；`auto` 优先 CUDA，可回退 CPU并返回原因。ORT Session 复用、图优化、线程上限、预热落地。provider 可用不等于所有节点在 GPU，验收使用实际节点 profile；RF 导出的 TreeEnsemble 算子可能仍在 CPU。

导出到新模型包，原包不覆盖。导出数值验证使用指定真实留出输入，保留 split、标签及阈值，重新生成文件 hash；固定验证 tolerance，拒绝不一致的导出。后续 TCN 必须另行训练并在同一冻结划分下评估，再导出相同模型到 ONNX 比较精度与时延。

## API 与部署

FastAPI `/v1/health`、`/v1/models`、`/v1/models/switch`、`/v1/models/rollback`、`/v1/recognitions`，附 OpenAPI。模型从服务端配置的别名目录选择；默认 127.0.0.1，单 worker 避免重复加载。上传请求在 ASGI 接收阶段以及文件读取阶段限制大小，临时文件始终清理。远程暴露需鉴权配置。

## 执行步骤与验收

- [x] 契约与管理器：推理/切换/回退/关闭并发安全，generation 单调递增，失败保留旧模型，旧实例释放；桌面录制切换回归。
- [x] 后端：旧 RF 校验兼容；ONNX 实际 Session 测试，概率/logits、序列/mask、形状、异常和设备选择覆盖。
- [x] API：真实 HTTP 入参/出参契约、上传限制与清理、线程调用、忙碌/错误、模型别名与生命周期验证。
- [x] 验收：真实 Libras 留出数据 RF/ONNX 数值与预测一致性、API 请求、P50/P95 时延及 GPU 实际算子证据。
- [x] 全量测试、wheel/CLI 检查，更新使用文档、验收报告和远程仓库。
