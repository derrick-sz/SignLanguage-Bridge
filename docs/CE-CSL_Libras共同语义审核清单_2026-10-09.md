## 专家如何填写与批准

每条 JSON 记录中的 `human_review` 保留 CSL 审核人、Libras 审核人、审核时间、决定、接受义项、拒绝义项、上下文限制、成对视频证据和版本。专家可以作出“接受词义对应”“仅限特定语境”“拒绝”“证据不足”等决定。两侧均需查看完整原视频；词条出现次数及中文句子只帮助选择材料。

1. 用 `libras_form.source_clip_examples` 找到原始来源片段，核对葡语业务意图和手语形式。保留隔离原因；隔离条目不能直接进入映射测试集。
2. 用 `csl_candidates.examples` 的 `sample_id`、官方 split、signer、CSV 行和资源路径查找 CSL 完整表达。对照 `sentence`、`raw_gloss`、规范化 gloss 与 Note。
3. 明确义项和映射类型，分别判断标签含义、手语形式、完整表达。可以词义对应但动作不同，也可以只有组件覆盖而没有成句对应。
4. 记录双方审核人、具体视频、上下文限制及版本后，才可给审核过的义项分配 `shared_semantic_id`。当前字段全部为空，`production_mapping_enabled=false`。
5. 动作/词级对齐以及成句翻译分别需要额外证据。CE-CSL 原始资料没有词级起止时间；CTC 时间步不能作为人工动作边界。

CSL 端稳定身份是 `sign_language=csl`、冻结数据标识 `dataset_id=CE-CSL`、原始 `token_id` 与词表 hash；Libras 端保留 `sign_language=libras`、`dataset_id=libras-eqt-uece-rgb` 与 `item:*`。语义引用可以一对多或多对多，不能替换来源键、改变 trained vocabulary 排序或把两种手语合为一个类别头。
