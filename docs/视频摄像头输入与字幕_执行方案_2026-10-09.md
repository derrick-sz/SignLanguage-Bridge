## 1. 交付范围和当前模型边界

- 视频文件：打开、预览、识别完整片段、显示中文和葡语；可取消及切换来源。
- 摄像头：选择设备、实时预览、开始/结束一次动作录制，结束后识别并显示字幕。
- 字幕：消费核心 RecognitionResult，以 label_id 查独立词典；显示来源、分数、拒识或错误提示。中文草案标注待核验，缺少中文不丢弃识别结果。
- 摄像头预览属于实时采集；本轮 RF 仍为 clip 模型，不开放 begin/feed/end 的模型流式能力，不把滑窗分类称为连续翻译。
- 当前模型包只有 pt-BR 文本。新增词典中文是显示草案，尚未经手语用户核验；不宣称完成中国手语识别或跨手语生成。

## 2. 模块和公共接口

| 文件 | 职责和公共接口 |
|---|---|
| slbridge/sources.py | FramePacket(image, timestamp, frame_index, source_id)；VideoSource(path)、CameraSource(index=0) 的 open/read/close/context manager；CapturedClip(frames, source_id)；ClipBuffer.append(packet)/finish()/clear() |
| slbridge/live.py | prepare_clip(clip, spec) -> PreparedInput；对捕获帧均匀选取最多配置帧数，沿用相同 Holistic 配置、resize、normalize_landmarks 和 prepare_array |
| slbridge/inference.py | 增加 Recognizer.recognize_clip(clip, sample_id=None)，与文件识别共用预测及结果结构 |
| slbridge/captions.py | CaptionCatalog.load(path)；caption_from_result(result, catalog, request_id, epoch) -> Caption；确定中文回退、草案状态和拒识文案 |
| configs/libras_caption_catalog.json | 12 个现有 label_id 的 pt-BR 和 zh-CN 显示草案，独立版本和审核状态 |
| slbridge/session.py | 不依赖 GUI 框架的后台任务、请求标识、取消与状态恢复；丢弃旧 epoch/request 的结果；工作量有界 |
| slbridge/desktop.py | 当前为 PySide6 预览、输入控制、中葡释义与设置；UI 更新留在主线程，捕获/推理工作放后台；首版 Tk 实施历史保留 |
| slbridge/desktop_widgets.py / desktop_presenter.py | 当前 Qt 视觉组件与可读文案映射；主字幕不显示内部编号，原始模型与结果信息保留在详细信息 |
| app/desktop_app.py | 新桌面启动入口；旧桌面原型保留至 app/legacy_desktop_app.py |

FramePacket.image 为未镜像 uint8 BGR 图像。文件使用媒体时间，可靠 fps 仅作显式回退；摄像头使用单调时钟。来源退出均释放 capture。录制缓冲在结束时以首帧为零点，不改变帧间时间。

ClipBuffer 默认限制 15 秒、600 帧和 128 MiB，保存等比例最大宽度 640 的帧；超过上限明确中止本次录制，不能悄悄丢弃动作开头。缺少两帧拒绝识别。每次开始、切源、取消或设备故障清空本次录制与当前字幕。

保留已有 slbridge/media.py 字节与 extractor identity，使已发布模型仍可直接加载；捕获帧复用其坐标处理和配置，不改变旧 schema。不得重新实现一套腕部/肩部归一化或推理默认值。

## 3. 状态与结果生命周期

`IDLE -> PREVIEW -> RECORDING -> PROCESSING -> RESULT/REJECTED`，来源或运行错误进入 ERROR，并提供重新打开/录制路径。

- 核心成功结果生成 final 字幕；本轮不产生 partial 字幕。
- 开始新动作、取消、切源、设备断开时清空旧字幕；拒识显示原因，不保留上一动作的成功文本。
- 每次请求带 request_id 和 source epoch；后台完成时必须同时匹配，旧任务不能回填新字幕。
- 模型与词典路径可配置；启动时检查模型支持 RGB clip，不能让旧63维模型接受新225维输入。
- 一个模型工作线程串行处理，不因点击多次建立无界队列。取消可丢弃结果，当前底层模型任务结束后释放 worker；不声称能立即中断 MediaPipe 原生调用。
- 预览采用最新帧有界缓存；文件预览按媒体时间播放，暂停不改变完整文件识别的内容。

## 5. 接口预检和验收重点

| 任务接口 | 生产与消费 | 预检结论 |
|---|---|---|
| 1 -> 2 | CapturedClip.frames 中 FramePacket 的 BGR、真实时间与固定source_id | 两路径均不得镜像；finish统一零点；采样发生在完整片段结束后 |
| 1 -> 3 | source.open/read/close 与 ClipBuffer | 捕获与UI分别负责资源/呈现；上限超出明确错误，不截断首帧 |
| 2 -> 3 | Recognizer.recognize_clip 与 recognize 返回同一 RecognitionResult | UI不直接调用RF，不重复处理关键点 |
| captions -> desktop | caption_from_result 返回 zh、pt、notice、status | 中文为草案必须可见；缺词典不阻断分类 |
| 所有任务 | 代码改动与当前模型hash | media.py保持不变，测试覆盖发布模型重载 |

验收优先检查：设备读取失败后释放；取消后的旧任务晚到；词典保存后显示真正变化；长视频与录制缓冲上限；拒识/无手后旧字幕失效。摄像头硬件不可用时记录事实，fake/replay检查不能冒充真人摄像头验收。
