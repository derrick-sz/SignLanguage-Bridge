# Libras 新增特征数据：算法策略与执行路线

日期：2026-10-10。范围：实际数据审计、模型策略及开发顺序。本轮运行了只读审计，未训练新模型、启动摄像头或更换已部署模型。沿用[模型选型研究](reports/streaming-model-selection-research-2026-10-10.md)的因果 TCN 主线，以下调整以本地文件为依据。

## 1. 新数据实际提供了什么

数据根为 `D:/Zenodo/Libras-EQT-UECE`。官方[Zenodo v4 发布](https://zenodo.org/records/21398895)同时提供 RGB、Landmarks 和 T 包；本地 README 对 landmark 的 CSV/JSON 描述与实际 NPY 文件不同，以文件审计结果登记输入。

| 资产 | 全量核查结果 | 算法用途 |
|---|---|---|
| 项目原始 RGB | 178 个非空条目目录，5,347 个 MP4 | 原始来源、提取器复现、后续视觉分支 |
| Hand Landmarks | 5,347 个 float32 NPY，全部 `[T,126]` | 手部序列输入、缺失分析 |
| 完整 Landmarks | 5,335 个 float32 NPY，全部 `[T,318]` | 手部与其余特征的分组时序模型 |
| 序列长度 | 两套均为 33～279 帧；中位 103，P95 为 185 | 保留可变长度，不默认压缩为 20／30 帧 |
| T 标注 | train/dev/test = 3,202 / 1,068 / 1,065，共 5,335 行 | 原发布划分、葡语文本监督 |
| T 图像帧 | 共 586,477 个 PNG，逐样本编号连续；每集合抽查 3 个样本首帧均为 256×256 RGB | 可复用的 RGB 预处理资产，尚不是神经网络 embedding |

5,335 对同相对路径的完整／手部 NPY 全部帧数相同，且全量逐值核验 `full[:,192:318] == hand`。因此手部 NPY 是完整数组的尾部子集，不能把两者拼接后宣称增加了新模态。Hand 额外 12 个文件位于条目 152、193 的各一个局部 informant 目录；它们有 RGB，但无对应完整 NPY，应登记缺失模态，不能补出虚构的 192 维。

全量数值检查无 NaN、Inf、`-999` 或读取错误。Hand 总计 587,575 帧，其中 137,355 帧的 126 维全零，约 **23.4%**；这说明手部缺失／不可观察状态需要单独建模，不能只看数组是否有限。全零帧不直接等于空闲动作，也不应删除后压缩时间。两个 63 维块的左右手身份、前 192 列内部点序、脸部点 ID、归一化及提取器版本仍待核验。

本地 landmark 无额外时间戳或提取器说明文件。数据集[作者论文版本](https://www.researchgate.net/publication/410629493_LIBRAS-EQT-UECE_A_Dataset_for_Isolated_and_Continuous_Brazilian_Sign_Language_Recognition_and_Translation)描述 106 点 xyz，并介绍 55 孤立项与 123 连续句；这些描述不能代替逐列映射和本地标签类型审核。当前 318／126 输入不兼容项目的 `mediapipe225_rgb_v1`／`hand63_v1`。

## 2. 先明确监督与评估边界

全部 5,335 行的 `original_info.label_gloss` 为 `[]`。`label_char` 是葡语词、标点及空格字符串构成的列表，共 176 个不同文本序列；字段名称不表示它已经是逐字符 tokenizer 或手语 gloss。

- **现在可以做**：已审核词条分类、固定短语／句式分类，输出对应审核后的葡语／中文含义。
- **另设研究实验**：用葡语自然文本训练编码器＋小型文本解码器，评价文本生成；它是无 gloss 的文本监督路线，不能冒充 gloss 识别。
- **后续 gloss CTC**：需获取并审核实际手语 gloss 序列。中文 CE-CSL 的 CTC 任务继续独立进行；不能将葡语按空格切分后塞入现有中文 gloss API。

176 文本标签与 178 原始条目不同：条目 22／31 共享“Desejo do mês de...”文本，99／114 共享“Oscilar.”文本。保留原条目 ID 与来源；经人工审核才能决定是否合并语义类别。纯按空白分词得到 44 个单词形态、132 个多词形态，这不是 55／123 手语任务类型的替代清单。含省略号等模板的标签不提供缺省月份、账户等实际值，字幕不能自动补全。

发布划分还有以下已核验问题：

1. dev/test 有 12 对同 ID、同标签、有序全部 PNG 内容 SHA256 相同的样本。
2. train 内有 6 对 `INFORMANTE 5` 与尾空格别名，全部 PNG 内容也相同。两项共证实 18 条冗余；这不是全数据所有重命名复制的去重结论。
3. 144／48／48 行 sample ID 包含真实换行 U+000A；明确替换为下划线后唯一对应 Windows 已解压目录，零碰撞、零缺失。保留原 ID、解析路径和规则，不修改原标注。
4. `INFORMANTE 1～5` 是局部标签，不能直接声明为全局独立签者。作者论文说明人员会跨条目轮换；真正的新签者评估需要全局人员映射或人工身份核验。

**协议处理**：原 split 与文件保持原样，登记为发布复现协议并披露重叠；另建立修正版 split，把确认同源／重复资源作为不可拆分组，消除 dev/test 交叉并去除 train 冗余。歧义来源、标签冲突、缺失模态单独隔离。原始媒体 hash、重复组和划分冻结后再训练；修正版最终样本数须由实际 manifest 生成，不能直接用 5,335 减去冗余数作为已就绪集。

资产关联审计另外区分严格来源与待审核候选：严格局部 informant＋文件 stem 有 5,199 条唯一、136 条歧义；明确去重音、标点与空白的候选规则可得到 5,287 条唯一、48 条歧义，但候选均为 `is_frozen_provenance=false`。5,287 个候选 hand、5,275 个候选完整 NPY 的长度分别与对应 PNG 数量相同；后者有 12 个缺失模态。可能来源集合还有 74 个跨 split 重叠组，尚未确认内容，不能与已经 hash 确认的重复混计，也不能省略后续核验。

## 3. 更新后的主模型

**主选：手部与其余特征分组编码＋共享轻量因果 TCN。** 第一轮用可核验的储存分组做向量时序对照，待点序确认后再增加关节拓扑。

```text
完整 float32 序列 [T,318]
  ├─ 已核验尾部 126 维手部特征 + 分块观察标记 → 小型投影
  └─ 前部 192 维其余特征 + 质量信息          → 小型投影
                      ↓ 合并时间特征
                共享轻量因果 TCN
                      ├─ 词条／固定句式分类
                      ├─ 葡语文本解码器（独立研究任务）
                      └─ gloss CTC（具备审核 gloss 后）
                拒识、端点确认、字幕稳定提交
```

具体策略：

- **输入契约先分离**：初版保留 `values[T,F]`、帧索引、来源和已验证分块；点序不完整时不假装已有 `[T,V,3]` 关节拓扑。后续冻结完整 `LandmarkSchema` 再转换关节结构。
- **缺失处理**：全块零值作为候选未观察标记；不能把每个零坐标都认作缺失。记录观察 mask，标准化统计只从训练折的有效值拟合。短期保持／估计必须仍标记未观察，不能使用未来插值。
- **时间处理**：NPY 的当前时间单位是帧索引。未核验原视频时间映射前，差分只能解释为每帧变化，不能写成每秒速度。在线使用实际采集时间戳；跨缺失段的差分要有独立有效 mask。
- **规模起点**：小投影＋4 个残差时间块，kernel=3、dilation=1/2/4/8；通道数在验证集选择。这是初始候选配置，不是已测最优结构。逐帧通道归一化或训练折冻结统计，不在时间轴上使用整段归一化来声明因果。
- **增量执行**：为每层卷积维护历史缓存，分类池化只累计已到达特征；分别记录网络前视、端点等待和字幕稳定等待。因果网络仍可能需要完整动作才能可靠区分类别。
- **扩展按错误决定**：确认点序后比较骨向量、有效差分、角度，再考虑小型空间 GCN；精细手形／遮挡错误明显时评估轻量 RGB。已有 TFNet 可作为离线视觉对照／教师，但新模型成绩以学生自身测试为准。

手部-only 模型用于低成本和缺失敏感性对照，不预设完整 318 维一定优于 126 维。若两者集成，收益属于同一数据不同建模方式的集成，应计入额外算力，不能当成多模态信息增益。

## 4. 必须安排的实验

| 实验 | 冻结输入／监督 | 回答的问题 |
|---|---|---|
| E0 原 RF | 历史 12 类及旧提取协议 | 保留旧工程结果，避免混写成新 178 类成绩 |
| E1 网络对照 | 修正版同源数据、相同 hand126 输入；RF／TCN／单向 GRU | 时间建模的增益；RF 固定长度适配独立记录 |
| E2 分组增益 | 相同来源集合，hand126 与 full318 分组 TCN | 其余特征能否改善误判，尤其手部不可观察片段 |
| E3 表示消融 | 核验点序后分别测试 xy／含 z、mask、运动、骨向量 | 把表示收益与网络收益分开 |
| E4 任务对照 | 审核词条、固定句式分别报告；文本生成另设任务 | 防止总体准确率掩盖句式识别退化或文本记忆 |
| E5 在线回放／摄像头 | 同一在线提取协议、缓存、端点及未知动作 | 流式质量、帧龄、误触发、动作结束到字幕 P50/P95 |

训练／验证折选择模型、阈值和拒识策略。标签频次、来源重复、局部 informant 分组、背景相关性一起审计；同源派生裁剪始终留在同一集合。分别报告 accuracy、macro-F1、逐类召回、覆盖率、未知动作误接收；真实 gloss 才报告 gloss WER。文本实验独立记录 tokenizer、文本评价、完整匹配和关键语义错误，并设置未见句式评估，不能仅凭固定模板测试声称自由交流。

在线测量计入关键点提取、模型、解码、排队和显示，两路同时运行另测。先比较 ONNX CPU／CUDA FP32，再检验 FP16 对输出和拒识阈值的影响；不在训练前承诺 90% 正确率或某个毫秒数。

## 5. 接入与开发顺序

1. **数据准备**：资产关联清单、原 ID／规范路径、模态缺失、标签类型、重复内容组、修正版 split；歧义候选不自动升级为可信配对。
2. **新输入适配**：新增 126／318 专用 importer 和输入版本；保持原 RF 输入不变。当前 `slbridge/contracts.py`、`features.py`、`runtime_contracts.py` 的白名单需要实际扩展，不能只替换权重。
3. **离线最小模型**：先完成一个可变长度 TCN 分类器的训练、评估、模型包保存与新进程推理；登记模型、数据、划分、预处理和标签 hash。
4. **在线提取一致性**：优先取得上游提取器及点序，复现 318 特征。如果无法复现，就从原 RGB 生成本项目定义的在线关键点版本并重训，318 模型保留为离线对照；不能把现有 225 维摄像头输入直接喂给 318 模型。
5. **流式状态**：begin/feed/end/reset、卷积缓存、上一帧时间、端点状态；模型热切换绑定 generation 并重置状态。输出复用已有任务结果，增加 partial／committed 和时间范围；真实 stream 能力实现前不在 manifest 宣告支持。
6. **一致性与实机验证**：同一前缀整批计算与不同 chunk 划分的增量 logits 相同；追加未来帧不改变旧帧 logits；断流、丢帧、换模型正确 reset。之后测摄像头与两路并发。

当前 `SequenceModelManifest` 只接受 TFNet RGB／CTC 模型包，不能直接承载骨架 CTC 或自然文本解码器。新增任务应扩展清晰的输入／输出契约，再复用已有 v2 序列结果中适用的部分。中文与 Libras 保持独立词表／任务头，审核后的中葡语义映射在识别结果之后完成。

预提取特征显著减少离线准备工作，但摄像头仍需要现场提取关键点。此次更新支持更完整的离线时序实验，尚未证明相机时延下降或新模型准确率提升。
