# 巴西手语 RGB 训练与验证

日期：2026-10-09（Asia/Shanghai）。本轮实现真实 Libras 视频到关键点、训练和独立视频推理的 F4 链路。实验指标和产物见[实验报告](reports/libras-rf-pilot-2026-10-09.md)。

## 1. 本轮范围

采用 Backbone 路线中预先选定的 E0 试点：条目 2、7、92、93、94、100、105、106、107、110、111、113，共 12 个来源条目、360 条视频。视频与词表都来自本地 Libras-EQT-UECE (RGB)，不使用旧 A–D 数据充当巴西手语。

模型任务为完整视频的有限条目分类。目录葡语文本作为类别显示文本保留，不将词或句子目录变成逐词 gloss，也不把有限目录分类称为连续翻译。

原始全量索引继续保持 5347 条视频、144 条标签冲突隔离。试点来自前期已检查的无字节重复集合；先冻结原视频的 local_informant 分组，再提取特征。该编号是条目内编号，不能据此声明跨全局签者评价。

## 2. 环境与运行

视频依赖放在项目内独立虚拟环境 `.venv-libras`，保留原 Python 环境。Python 3.12.7、NumPy 1.26.3、scikit-learn 1.4.0、joblib 1.4.2、OpenCV contrib 4.10.0.84、MediaPipe 0.10.14。

```powershell
python -m venv .venv-libras
.venv-libras/Scripts/python.exe -m pip install -r requirements-libras.txt
.venv-libras/Scripts/python.exe -m experiments.libras_rf
```

实验使用已有全量索引 `artifacts/datasets/libras-rgb/manifest.json`。默认输出 `artifacts/experiments/libras-rf-pilot-20261009/`。它先建立源数据子集和冻结 split，再提取并生成对应特征 split，随后训练模型。重复运行会校验并复用成功缓存；实验定义变化时应使用新的 `--work-dir`。

```powershell
.venv-libras/Scripts/python.exe -m experiments.validate_libras
```

这个命令由另一个 Python 进程加载已训练模型，每个类别取一条事先冻结的测试视频，检查原始视频推理、原始视频与缓存特征的一致性，并保存测试混淆矩阵。它不参与模型或阈值选择。

## 3. 新输入契约

`mediapipe225_rgb_v1` 与旧 `pose_hands225_legacy` 分开。新表示保存 33 身体点＋左手 21 点＋右手 21 点的坐标和缺失状态，包含真实采样帧编号、时间戳和提取器来源。

- 对每个视频完整解码并核对声明帧数，均匀选择最多 30 帧用于提取；缩小到最大宽度 640，保留原图比例。
- 使用 MediaPipe Holistic 的身体与解剖左右手输出；每个片段开始前重置追踪，不镜像视频。模型资源随安装包提供，固定 complexity=1，不在运行中下载新的提取权重。
- x/y 经画面比例校正，以双肩中点为原点、肩宽为尺度。第三坐标明确为 0，不把不同来源的 z 值拼成未经校准的三维骨架。
- 不可见点完整 xyz 标记为 -999；模型输入转成坐标＋mask。RF 的 30 帧特征为 13,500 维。增强若启用只影响训练中的已观测 x/y，不扰动恒定 z 或缺失坐标。
- 使用解码 POS_MSEC 的递增时间；不可用时采用视频自身 fps 与帧编号并记录 fallback，不补写一个默认 fps。
- 默认至少 80% 抽样帧有有效肩部参照、至少 10% 抽样帧有一只可见手；不合格视频记录明确拒识原因。
- 时间重采样、缺失 mask 和质量检查在训练、NPZ 推理及原始视频推理中共用。完整视频模型当前需要整段输入，尚未声明流式能力。

实际提取接口参照 [MediaPipe 0.10.14 官方 Holistic 源码](https://raw.githubusercontent.com/google-ai-edge/mediapipe/v0.10.14/mediapipe/python/solutions/holistic.py)。点序和肩部索引参照[官方 Pose 定义](https://raw.githubusercontent.com/google-ai-edge/mediapipe/v0.10.14/mediapipe/python/solutions/pose.py)。

## 4. 缓存和来源保留

每个 NPZ 作为一次原子提交，包含 values、timestamps、frame_indices 和 JSON metadata，不依赖 pickle。缓存键绑定源视频 hash、样本 ID、完整提取配置、代码 hash、依赖版本和模型资源 hash。

派生记录保留原始 sample_id、label_id、语言、显示文本和分组，并通过 derived_from 和 raw_source_hash 关联原视频。即使不同原文件产生不同 NPZ 字节，它们的相同原始内容也不能进入不同集合。

只向独立、具有所属标记的特征目录写入。中断后已验证的成功缓存保留；损坏 ZIP/压缩内容重提取；源字节变化时停止，不能复用旧缓存。依赖或程序错误直接失败，解码／质量失败单独隔离。

`project_split` 保持提取前的源分组分配。失败样本及其不可拆分组进入 excluded，不重新随机分配剩余样本；若因此缺少类别覆盖，明确失败。

## 5. 通用 CLI

可使用核心 CLI 对任何已索引的 RGB 子集进行提取，然后沿用现有训练接口：

```powershell
.venv-libras/Scripts/python.exe -m slbridge extract --manifest artifacts/experiments/libras-rf-pilot-20261009/source_manifest.json --output-dir artifacts/experiments/libras-rf-pilot-20261009/features --output-manifest artifacts/experiments/libras-rf-pilot-20261009/feature_manifest.json
.venv-libras/Scripts/python.exe -m slbridge train --manifest artifacts/experiments/libras-rf-pilot-20261009/feature_manifest.json --split artifacts/experiments/libras-rf-pilot-20261009/feature_split.json --config artifacts/experiments/libras-rf-pilot-20261009/training_config.json --output-dir artifacts/models
```

对原始视频推理时，使用 `slbridge predict --model 模型包目录 --input 原始视频.mp4`。同一模型也接受具有完全匹配的提取契约的 NPZ。旧 NPY 不能伪装成新 RGB 格式。

模型包记录实际提取契约与依赖版本。原始视频推理前核对提取器身份；NPZ 推理无需原视频，也不隐式替换提取参数。
