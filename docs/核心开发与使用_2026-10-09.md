# 核心开发与使用

日期：2026-10-09（Asia/Shanghai）。首轮 F0–F3 已实现并用本地真实 NPY 数据验证。开发依据为[核心框架设计](核心框架设计_2026-10-09.md)。

> 后续实现更新：F4 的真实 Libras RGB 提取、训练与独立视频推理已经完成，详见[巴西手语训练与验证](巴西手语训练与验证_2026-10-09.md)。本文重点介绍首轮 NPY 用法。

## 1. 已有能力和接口

| 模块 | 公共入口 | 本轮实际行为 |
|---|---|---|
| contracts | SampleRecord / DatasetManifest / SplitManifest / InputSpec / RecognitionResult | 版本化字段、稳定 ID、语言与显示文本分开、未知身份保留空值 |
| data | import_legacy / import_libras / save_manifest / load_manifest / verify_manifest / create_split / validate_split | 原数据只读；原子幂等索引；冲突隔离；重复、同源、派生与声明组不跨集合 |
| features | prepare_input / prepare_array / feature_vector | 训练与推理共用确定性处理；严格区分 63/225；保留缺失 mask |
| models | RandomForestBackend.train / save / load / predict_proba | 实际 RF；增强仅由训练样本生成；完整输入契约随权重保存 |
| training | TrainConfig / train | 不可变的解析配置；验证集选阈值；测试集最终评价；新模型包原子发布 |
| bundle / inference | load_bundle / Recognizer.load / recognize | 先检查完整产物和契约再加载权重；离开原训练数据也能推理 |
| CLI | index / validate / split / train / predict | 无 GUI 环境可调用；成功输出 JSON，配置／格式错误输出 JSON 并返回退出码 2 |

任务目前只有 classification，能力为 clip。连续序列、文本翻译、流式会话和第二个 backbone 尚未声明可用。RGB adapter 用于索引；原视频经实际提取成为带时间戳的 NPZ 后进入相同训练器，新 RGB 模型支持直接识别原视频。

## 2. 安装和入口

使用项目根目录作为工作目录。推荐 Python 3.12；本轮实测解释器为 `D:/anaconda3/python.exe`，Python 3.12.7。运行核心无需安装旧 `requirements.txt` 中的媒体和 GUI 依赖。

```powershell
python -m pip install -r requirements-core.txt
python -m slbridge --help
```

`pyproject.toml` 同时提供包元数据、可选测试依赖和 `slbridge` console 入口；按项目方式安装后也可以使用 `slbridge ...`。直接在根目录运行 `python -m slbridge ...` 即可。

## 3. 单手 63 维的完整流程

```powershell
python -m slbridge index --source legacy --root data/sequences --dataset-id legacy-hand63 --representation hand63_v1 --output artifacts/datasets/legacy-hand63/manifest.json
python -m slbridge validate --manifest artifacts/datasets/legacy-hand63/manifest.json
python -m slbridge split --manifest artifacts/datasets/legacy-hand63/manifest.json --seed 42 --output artifacts/datasets/legacy-hand63/split.json
python -m slbridge train --manifest artifacts/datasets/legacy-hand63/manifest.json --split artifacts/datasets/legacy-hand63/split.json --config configs/rf_hand63.json --output-dir artifacts/models
```

训练默认生成唯一 run_id，在标准输出返回模型目录与评价。需要明确命名时添加 `--run-id 自定义版本名`；重复命名会失败，已有模型不被覆盖。本轮已生成 `artifacts/models/core-hand63-20261009/`。

```powershell
python -m slbridge predict --model artifacts/models/core-hand63-20261009 --input data/sequences/A_000.npy --sample-id request-001
```

Python 调用接口：

```python
from slbridge.inference import Recognizer

recognizer = Recognizer.load("artifacts/models/core-hand63-20261009")
result = recognizer.recognize("data/sequences/A_000.npy", sample_id="request-001")
print(result.to_dict())
```

返回 `recognized` 或 `rejected`；格式／契约损坏会抛出明确错误。不会因为缺少中文或葡语显示文本而删除标签。分数是 `uncalibrated_class_probability`，低分拒识不等同于已经验证的词表外检测。

## 4. 225 维和 RGB 来源

全身双手数据单独指定 `pose_hands225_legacy`，使用 `data/sequences_full/` 和 `configs/rf_pose225.json`，不能把 225 维文件当成单手文件取前 63 维。

```powershell
python -m slbridge index --source legacy --root data/sequences_full --dataset-id legacy-pose225 --representation pose_hands225_legacy --output artifacts/datasets/legacy-pose225/manifest.json
python -m slbridge split --manifest artifacts/datasets/legacy-pose225/manifest.json --output artifacts/datasets/legacy-pose225/split.json
python -m slbridge train --manifest artifacts/datasets/legacy-pose225/manifest.json --split artifacts/datasets/legacy-pose225/split.json --config configs/rf_pose225.json --output-dir artifacts/models
python -m slbridge predict --model artifacts/models/core-pose225-20261009 --input data/sequences_full/A_000.npy
```

Libras 视频的索引与组划分：

```powershell
python -m slbridge index --source libras --root "Libras-EQT-UECE (RGB)" --dataset-id libras-eqt-uece-rgb --output artifacts/datasets/libras-rgb/manifest.json
python -m slbridge split --manifest artifacts/datasets/libras-rgb/manifest.json --group-field local_informant --output artifacts/datasets/libras-rgb/split.json
```

全量索引重跑会读取约 8.98 GB 视频用于 hash。Libras 标签按条目 ID 保存，葡语名称仅用于显示。同名条目不自动合并。`local_informant` 的值包含条目 ID，不代表全局签者；这份划分不能声明 signer-independent。144 条相同内容但标签冲突的记录已隔离，实际 split 包含 174 个条目。

## 5. 输入处理约定

- `hand63_v1`：21 手部点×xyz，历史坐标保留，不再次默认做腕部归一化；不接受 -999。
- `pose_hands225_legacy`：身体 99＋左手 63＋右手 63；-999 转为零并保存逐坐标 bool mask。RF 特征包含坐标和 mask；30 帧对应 13,500 维。
- 两种来源的实际归一化、镜像与采样细节沿用遗留资产，未经核验的信息不能补写成事实。representation_id 是点序与旧格式版本约定。
- 仅接受二维 float32/float64、严格宽度与有限数值；对象数组、NaN/Inf、隐式截断和 float32 溢出拒绝。
- 统一按相对帧位置重采样到配置中的 target_frames，不从帧数推测 fps。相邻缺失坐标不参与插值；缺失状态不会被填成伪观测。
- 有效坐标不足或少于两帧返回质量拒识。训练遇到质量拒识会明确失败，要求修订索引与冻结 split，不静默丢弃样本。

## 6. 配置、数据划分与模型包

训练 JSON 必须声明 representation_id；未知键和错误类型被拒绝。RF 参数目前支持 n_estimators、max_depth、min_samples_leaf、n_jobs。种子必须与冻结 split 一致。augmentation_repeats 默认 0；设置增强后也只处理训练集。

threshold_candidates 的选择仅使用 validation，在满足 minimum_validation_coverage 的候选中优先选择 accepted_accuracy，再选择覆盖率和较低阈值。test 不参与选择。当前示例配置包含 0、0.5、0.7；本次真实数据选择 0，因此不进行分数阈值拒识，质量拒识仍有效。

默认 60% / 20% / 20%，根据不可拆分组件近似比例分配，保证每个可用类别在三集合中存在。无法满足的约束会报错。要求未知 signer_id 分组也会报错。冻结 split 路径已有不同定义时 CLI 拒绝替换，应使用新路径记录新实验。

```text
artifacts/models/{run_id}/
  manifest.json
  labels.json
  resolved_config.json
  weights/model.joblib
  splits/dataset.json
  splits/split.json
  metrics.json
```

模型包记录数据与 split hash、输入处理契约、实际参数、代码 hash、依赖版本、类别顺序、分数类型和每份产物的 SHA256。原子发布前真实重载并核对预测；正常失败清理当前暂存目录。进程被强制终止可能保留隐藏 `.partial` 目录，后续运行生成新版本，不把残留目录当成有效模型。

运行时检查完整契约、实际 RF 参数／种子及依赖版本；当前采用依赖精确版本匹配。校验和用于检测损坏与组合错误，joblib 权重只加载可信本地训练产物。推理不访问原训练样本。无拟合统计量的当前处理链通过 `preprocessing_state: none` 明确记录。
