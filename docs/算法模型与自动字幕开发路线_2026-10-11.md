日期：2026-10-11（Asia/Shanghai）。状态：brainstorming 路线讨论稿；用户已确认首版交互为“每做完一个词或短句稍作停顿，系统自动追加字幕”，并选择 LLM 第一阶段增强“中葡表达辅助：将已识别词义组织成句子，歧义时请求确认”。模型选择、参数和验收数字是待实验验证的建议。本次交付规划与证据核对，未运行新训练、摄像头或 LLM 验收。

## 1. 近期目标与路线选择

近期交付：摄像头持续采集 → 自动提取一个完整动作 → 识别词或固定表达 → 查经审核的中葡释义 → 按动作顺序追加字幕；支持拒识、撤销与重新表达。保留动作内部的时间信息，先不处理多个动作之间的语法重排。

长期目标仍是中国手语与巴西手语 Libras 使用者的双向交流。文字辅助是其中一个阶段；目标手语表达、自然句转换、远程双设备和更自由的连续表达另设里程碑。场景是可选元数据，不作为本轮内核的必填条件。手语体系、模型标签语言、字幕语言分别登记。

| 路线 | 收益 | 数据与工程代价 | 决定 |
|---|---|---|---|
| 停顿分段＋完整片段分类＋字幕事件 | 可利用现有 Libras 词/固定表达数据；错误容易定位 | 需自动端点、负例、在线特征及中文孤立词数据 | 首版主线 |
| 无刻意停顿的连续识别＋CTC/其他序列解码 | 可输出可变长度词序列 | 需要可靠序列监督、对齐与更复杂的提交策略；现有中文候选质量不足 | 中文研究分支保留，随后扩展 |
| 视频直接生成目标语言句子或目标手语 | 面向更开放的交流 | 需要足够的语义/文本监督及目标表达验证；现有跨手语对齐不足 | 长期研究入口 |

**持续采集可以配合片段模型。**首版在动作结束后调用 clip 分类，不以实现零前视网络、每层增量缓存或 CTC 为前置条件。TCN 的因果卷积是未来优化的基础，但当前模型仍以完整片段训练和评价。系统能力应分别声明“持续采集、自动分段、clip 推理”，不把它登记成模型原生 stream 能力。

## 5. 模型路线：先解决输入与监督，再增加复杂度

首选结构是“明确版本的关键点序列＋缺失信息 → 轻量 TCN → 语言专属分类头”。首版用完整动作上的交叉熵训练，保留可变长度和有效步掩码。Libras 与中文可以复用实现，但分别训练权重和词表；是否共享编码器是后续实验结论。

| 顺序 | 候选 | 启动条件与判断依据 |
|---|---|---|
| A0 | 当前 RF/现有 TCN | 保存已知基线和回放夹具，确认输入身份 |
| A1 | 轻量 TCN 分类 | 首选；有可靠孤立动作/固定表达标签，输入与在线一致 |
| A2 | 单向 GRU 分类 | 一个低成本结构对照；同数据、输入、划分比较质量与完整链路成本 |
| A3 | 小型空间 GCN＋TCN | 手与身体相对关系的错误显著，并且节点顺序/拓扑已冻结时再试 |
| A4 | 关键点＋轻量手/脸 RGB 分支（如 MobileNetV3） | 细手型、口形、遮挡等错误分析支持新增信息时再试；计入裁剪与视觉提取成本 |
| R1 | TFNet、改进视觉表示＋TCN/其他序列模型＋CTC | 连续中文研究线，独立于首版孤立动作交付 |

这些是项目选型建议，不是已证实的性能排名。TCN 的通用依据见 [原论文](https://arxiv.org/abs/1803.01271)；骨架多流思路见 [SL-GCN 作者实现](https://github.com/jackyjsy/CVPR21Chal-SLR/blob/main/SL-GCN/readme.md)；轻量 RGB 候选见 [MobileNetV3](https://arxiv.org/abs/1905.02244)。原版全片段 GCN/注意力可以用于已结束片段，但迁移到增量输出时要另审未来帧依赖。

**Libras 输入是首要工程门槛。**原 318 列的点序已有强证据候选，但提取器版本、所有数值和全量时间映射还未冻结。原应用 225 维不能靠补零或截取喂给 321 维 TCN。两条可选路径：

- 能复现原协议：在多种真实训练/验证片段上核验点序、左右手、时间、缺失策略、归一化及数值差异，再评估线上质量。
- 不能达到可用一致性：用本项目明确版本的提取器从 RGB 重提并重训，旧 321 维模型保留为离线对照。新表示不一定仍为 321 维。

对新协议，要同时保留相对身体的手部位置和局部手型；身体、脸、手的 z 不能默认共用物理坐标系。不要把零坐标逐元素当缺失，不把手部丢失当静默。涉及反向、镜像、裁剪、速度变化的增强须检查标签含义，训练增强与测试隔离。

先完成片段推理，再按瓶颈将提取前移到采集阶段。连续 tracker 的历史状态与训练逐片段 reset 可能产生不同特征，应通过回放和再训练验证；不能直接承诺常驻 tracker 与旧缓存完全一致。ONNX FP32 对齐后比较 CPU/CUDA；只有收益明确才验证 FP16 或增量缓存。

## 6. 自动分段与字幕事件如何落地

首版用户只需完成一个词/固定表达并稍作停顿。暂停检测负责提出动作结束候选；分类器负责解释这个完整动作；字幕控制器负责是否提交与去重。

```mermaid
flowchart LR
    A[摄像头或按时间回放的视频] --> B[带时间戳的有界缓冲]
    B --> C[活动与质量观察]
    C --> D[停顿端点及完整片段]
    D --> E[对应语言的片段识别器]
    E --> F[质量与未知拒识]
    F --> G[动作事件及审核释义]
    G --> H[字幕记录 追加 撤销 清空]
```

分段状态建议为 `WAITING → CAPTURING → END_CANDIDATE → SEGMENT_READY → REARM`，推理另设独立工作状态。检测到“运动减少”不能直接解释为动作完成：静态手型、动作内部停顿、追踪丢失都会造成低运动。起始判断综合手部可见性、相对位置/手型变化与持续性；端点结合有效观察、停顿与最短持续时间。需要保留起点前缓冲和结束尾部，减少截断。

停顿阈值可在验证集比较 0.3/0.5/0.7 秒，作为起始实验网格；最终只发布验证选中的配置。最短/最长段、重启条件和各阈值跟随模型/分段配置版本。没有手或遮挡时进入质量中断判断，不能把不完整动作自动确认成成功。超长段明确拒绝/请求重做，不静默切掉开头。

提交后持续保持同一个手型，不应重复产生新字幕；识别到一次新的动作起点后，相同标签可再次提交。静态重复可以通过释放再做或人工确认辅助。对固定短句中的短暂停顿，必须测量误切率；当停顿约定仍不足以分开词内停顿与结束，可增加小型活动/边界模型，标签需来自真实长流。

| 模块建议 | 责任与最小接口 |
|---|---|
| `AutoSegmenter` | 消费带真实时间戳的观察；返回完整片段或拒绝原因；可 reset；不负责翻译 |
| 模型 adapter | 接收符合自身 InputSpec 的完整片段/特征；返回现有 classification 结果；申明 clip 能力 |
| `GestureEvent` | session/source epoch、event/segment ID、语言、模型 generation、表示版本、起止时间、标签、分数类型、质量及拒识原因 |
| `CaptionTimeline` | 按 event ID 幂等提交；按源事件顺序追加；撤销/清空有显式事件；模型更换后的旧结果不能回填 |
| `CaptionCatalog` | 保留原标签与审核中葡释义；语义引用可空；缺译文不丢失合法识别结果 |

首版“候选区”可先显示“正在采集/识别”，只有验证过前缀分类可靠性后才显示提前预测。候选不进入正式字幕；拒识不追加旧成功文字。原始字幕记录按确认事件拼接。第 11 节的 LLM 辅助表达另设草案/用户确认记录，不覆盖原始字幕，不自动补出未经证据支持的完整句子。

复用 `sources.py / session.py / runtime.py / captions.py / desktop.py`，新增分段和字幕记录的独立模块，不把状态机写入 GUI。采集与推理独立；预览采用最新帧，动作片段必须保留顺序。排队有界，满时给出忙碌/本次未识别事件，不能无声丢弃已完成动作。换源、断流、取消、换模型分别 reset 分段状态并隔离迟到结果；历史已确认条目的保留或清空通过显式操作完成。

本地首版可复用现有 clip API，由采集端提交分段片段。需要远端事件传输时再增加明确版本的会话事件接口；不要每帧上传图像并重复加载模型。双语同时服务时配置语言/会话路由和独立状态，热切换负责版本更新。共享 GPU 可串行调度模型计算，不要求每种语言同时占满 GPU；两路延迟另测。

## 7. 数据与实验最小集合

| 实验 | 控制变量 | 输出和用途 |
|---|---|---|
| E0 输入一致性 | 同一视频、模型、确定性处理 | 在线路径与训练路径的形状/时间/数值/输出差异；不通过则重提重训 |
| E1 分类对照 | 同一语言、词表、来源集合和输入 | TCN vs GRU；必要时同输入 RF，报告 macro-F1、逐类召回、成本 |
| E2 特征对照 | 固定 TCN 和划分 | 手部 vs 含上身/面部；mask/运动逐项加入，不一次改变多个因素 |
| E3 端点与负例 | 固定分类权重、真实未切长流 | 停顿配置、误切/并段、漏事件、空闲误触发、真实重复和未知误接收 |
| E4 自然使用验证 | 冻结整条管线，新签者/设备 | 正确提交事件率、覆盖率、纠错次数、P50/P95、内存与队列 |
| E5 部署对照 | 同权重和真实输入 | PyTorch vs ONNX、CPU vs CUDA；FP16 按需，核对预测及拒识行为 |

新增录制至少覆盖：静态保持、正常动态、动作内暂停、连续两个不同动作、连续两个相同动作、固定短句、手部出框、光照/距离变化、非手语日常动作及未收录手语。标注真实起止和含义，记录签者/场次；不能只把已切片视频机械拼接成唯一在线测试。合成拼接可用于工程冒烟，真实长流用于验收。

没有边界真值时无法可靠评价分段。语料中的停顿和动作起止要分别标记；idle、transition、occlusion、unknown 与 known-label 分开统计，不能把未知都塞进一个保证解决开放集问题的类别。

## 8. 阶段顺序与退出条件

| 阶段 | 开发与数据工作 | 退出条件 |
|---|---|---|
| M0 整理可复现基线 | 明确应用与实验分支；选择后续开发基线，冻结模型/词表/预处理；保存回放夹具 | 新进程能加载对应模型；界面/API清楚显示任务和输入版本；实验模型不会自动取代应用模型 |
| M1 字幕事件与回放 | 完成 timeline、幂等提交、撤销/清空、时间戳与延迟埋点；先接已有片段识别 | 同一事件只追加一次，真实重复可再次追加；旧 epoch/generation 不回填；回放与接口结果可追溯 |
| M2 Libras 自动动作闭环 | 解决在线特征一致性/必要重训与模型包接入；停顿分段、负例、拒识；持续采集接 Qt | 用户不点每次结束按钮也可逐动作追加；固定短句/停顿/重复/未知有真实回放与摄像头证据 |
| M3 中文孤立动作与双语词典 | 申请/补采中文孤立词；同框架独立分类头；双方审核共同表达与译文 | 两侧分别达到事件指标；未审核项明确标记；不会用标签翻译替代另一语言训练 |
| M4 性能与可靠性 | 提取缓存/必要增量、ONNX部署、两路路由、长时间压力与新用户验证 | 质量与端到端延迟同时满足冻结门槛；无无界积压、串会话或显存持续增长 |
| M5 连续理解与目标表达 | 更自由边界、序列/文本监督、目标手语资产；再连接远程会话 | 新任务有独立数据与评价，不以字幕拼接成绩代替自然交流能力 |

M1 与中文数据/词义审核可并行，M2 的高质量接入依赖特征一致性，M3 不阻塞 Libras 的工程验证。TFNet/中文 CTC 的研究实验使用单独预算和配置，不阻塞逐动作首版。日历排期在数据获取、重提吞吐和人员审核条件核实后给出，避免把申请/标注时间隐藏在训练轮数里。

下一次实际开发建议范围为 **M0＋M1＋M2 的按时间回放验证**：先给出可检查的动作事件与字幕记录，再接停顿分段；相机验收在选定可用模型包和输入协议后进行。现有 RF 可用于功能冒烟，但其结果不得冒称 174 类 TCN 效果。

## 9. 建议验收指标与延迟预算

下面是首版试点的候选目标，不是已达到的能力或行业标准。先做小规模标注试验估计难度，再于正式留出测试前冻结门槛。不能在看到测试结果后降低门槛并宣称原目标已达成。

| 指标 | 建议目标/口径 |
|---|---|
| 已确认字幕事件的正确率 | ≥95%；分母为全部正式提交事件，空闲误触发、重复误追加和错标签均计错 |
| 词表内动作正确提交召回 | ≥85%；拒识、漏检、误切导致的漏提交都计入，防止全拒识取得高精度 |
| 词表外动作误接收 | ≤5%；独立已标注未知动作事件为分母 |
| 空闲误追加 | ≤0.2 次/分钟；记录累计有效空闲时长，不能只测几秒 |
| 多余重复字幕 | ≤1 次/100 个参考已知动作；同时报告真实重复被错误合并的次数 |
| 动作结束 → 字幕绘制完成 | 首版 P95 ≤2 秒；优化目标 ≤1 秒；两者均为待验证工程目标 |
| 双语表达 | 审核目录内逐项核对义项、否定、数量及模板槽位；报告审核覆盖范围 |

事件匹配按时间顺序一对一，冻结边界容差与重叠规则；一段动作输出多次只能有一次匹配，余下计误追加。每侧单独报告分子/分母、逐类表现与拒识覆盖；首批试点建议至少 3 名未参与训练的签署者、300 个词表内事件、100 个词表外事件及累计 30 分钟空闲。小试点不能代表所有人群，必要时报告签者级区间；类别覆盖不足时收缩声称的可用词表。

延迟使用同一会话单调时间记录：人工标注动作结束 → 端点确认 → 排队 → 尚未完成的特征提取 → 模型/后处理 → 释义/字幕绘制。在线并行提取的重叠成本不能重复相加；统计实际整条事件时延，同时报告采集帧龄、吞吐、丢帧和阶段耗时。提前输出要单列提前量和准确率，不能用负延迟改善最终确认指标。冷启动/预热单列，至少比较本机 CPU/CUDA 和双路并发，不把历史 0.604 ms 当端到端预算。

## 10. 本轮决定与仍需验证的事项

已确认：首版是词/固定表达后短暂停顿的自动字幕；共享框架、两侧独立标签与模型；场景不成为前置条件。

建议主线：Libras 现有数据＋兼容的在线关键点协议＋TCN 分类；中文优先孤立词数据＋相同类型的分类基线；分段与字幕事件是独立功能。TCN不是不可替换的架构约束。后续的 GCN、RGB 融合、蒸馏、量化及持续序列翻译均以错误/成本证据触发。

仍需验证：原 318 协议能否达到可用一致性；中文数据申请/词义交集；真实长流分段、未知拒识和新签者质量；审核双语释义；端到端时延与双路负载。一个高分类分数、一次成功字幕或 GPU provider 已加载，都不能代替上述证据。

本稿与 [核心框架设计](核心框架设计_2026-10-09.md)、[总体交流路线](中巴手语实时交流_总体架构与路线图_2026-10-09.md)衔接。旧模型选型中“先做两侧连续 CTC/增量缓存”的顺序，在本次已选定的逐动作交互下调整为后续研究；原报告的已测结果保持原样。

## 11. LLM 与中葡表达辅助智能体

用户已选择第一阶段优先“将已识别词义组织成中葡句子，歧义时请求确认”。建议增加可插拔的单智能体，消费正式动作事件、已审核词义与用户确认的会话上下文，输出双语表达草案或澄清问题；不进入逐帧识别关键路径。

功能链路为：**原始识别字幕即时显示 → 选择本句事件 → 检索审核词义/表达 → LLM 组织草案 → 来源与语义约束检查 → 用户确认辅助表达**。词后停顿只定义动作边界；首版以“整理本句”确定句界，不能每个词停顿就擅自补全一句。界面区分原始识别、辅助表达与待确认信息。

LLM 按 `semantic_assistance` 独立任务和 API 接入，共享 trace/版本外层，保留生成专用 payload。定义 `LLMProvider`、事件快照、审核语义目录、限定上下文、草案校验和确认记录；复用模型 API 思路，但不强制 LLM 使用分类结果、分类分数或当前 ONNX 运行时。云端和本地模型通过适配器更换，具体型号以中葡语料、时延与资源测评决定。

边界：LLM 不修改原识别、不把漏词补成事实、不凭上下文纠正标签、不把未审核译文标成 reviewed；歧义必须澄清。草案绑定 session/source epoch、事件与 timeline/context/catalog revision，撤销、清空、更正后迟到结果不可回填。超时/断网只影响辅助层；原字幕继续。规则与结构化 JSON 只能检查部分错误，不能保证自由文本含义完全忠实。

新增 **L0 契约与评估集 → L1 审核词义/模板 → L2 单 provider 表达与澄清 → L3 本地/双路部署 → L4/L5 开放交流及视觉研究** 分支。L0 可随 M1 搭接口，L1 复用 M3 审核；L2 不阻塞 M2 摄像头闭环。目前共同语义审核 0 项，工程夹具或人工文本样例可以先行，不能宣称已完成正式双语辅助。

验收增加语义忠实、无依据内容、缺义/歧义澄清召回、有效表达覆盖、中葡分别审核，以及句末到辅助草案时延、会话隔离和失效回退。原路线动作结束到原始字幕的时延与识别指标独立保留。LLM 能否改善实际交流成功率是待验证假设，不以语言流畅度代替识别正确率。

完整模块、接口、数据和接入顺序见 [LLM 中葡表达辅助智能体设计草案](LLM中葡表达辅助智能体_设计草案_2026-10-11.md)。本轮只补充设计，不实现 LLM 或更改已启动开发会话的任务范围。
