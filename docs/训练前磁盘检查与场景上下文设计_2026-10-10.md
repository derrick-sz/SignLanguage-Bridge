## 2. 首轮特征训练的新增预算

预算假设：小型因果 TCN 不超过 500 万参数；复用已有可选 PyTorch/CUDA 环境；从现有 NPY 按需读取；增强在线生成；不再复制原 RGB/PNG，不重新解压 T ZIP。以下均为规划估算，尚无真实训练峰值。

| 新增项目 | 首轮预算 | 控制方法 |
|---|---:|---|
| 输入索引、派生值/mask/有效差分缓存 | 1～3 GiB | 每个输入协议只生成一次；训练折统计独立；避免各 seed 重复缓存 |
| 有限检查点、ONNX、模型包及保存临时副本 | 1～2 GiB | 保存 best/last 和有限恢复版本，不保留每一轮全部权重 |
| 清单、预测、指标与日志 | 0.2～1 GiB | 不将每轮全部帧的中间激活写盘 |
| 其他短期文件余量 | 1～2 GiB | 限制缓存与诊断输出 |
| 合计控制上限 | 10 GiB | 上述上限合计 8 GiB，另留 2 GiB 波动余量 |

算术校验：500 万参数的 float32 权重约 0.0186 GiB；若恢复文件含权重和两个 Adam 状态，核心张量约 0.0559 GiB/份。每组最多 5 份、3 个 seed 合计约 0.8382 GiB，另计缓冲区、导出、打包和原子保存暂存。此估算仅适用于这个小型 TCN 假设，不适用于完整 TFNet。

建议输出根为 `D:/SignLanguage-Bridge-runs/libras-tcn`，缓存根为 `D:/SignLanguage-Bridge-cache`，都在只读数据集目录之外。目录尚未创建，训练器仍需显式支持这些配置。10 GiB 用完时 D 盘按快照还剩约 81 GiB；建议再保留 15 GiB 未使用余量，并在缓存、训练、导出开始前重查空间。这些预算/检查尚未实现为自动保护。

当前 CLI 的训练默认输出为 `artifacts/models`，落在 E 盘；采用上述 D 盘安排时需要显式指定输出，不能只在文档里更改。现有 `artifacts/cecsl-integration-20261009/venv/Scripts/python.exe` 解析到已有 `torch 2.9.1+cu130`、`torchvision 0.24.1+cu130`，模块位于 `D:/anaconda3/Lib/site-packages`。这支持复用环境的空间预算假设；本轮未加载权重或初始化 GPU，实际训练仍应冻结依赖并验证 CUDA 可用性。

磁盘足够不等于训练已就绪：当前 [training.py](../slbridge/training.py) 仍是 RF 训练入口，126/318 适配、修正版 manifest/split、TCN 训练与加载需要开发。歧义配对、重复组、标签类型仍按新数据策略先冻结；本次没有检验 GPU 显存或训练收敛。

## 3. RGB 路线的空间边界

现有 PNG 已可按需解码，训练不必把全部图像复制到未压缩缓存。对 586,477 帧的理论体量计算如下，未实际创建这些缓存：

| 新增缓存形态 | 理论数值体量 |
|---|---:|
| 256×256×3 uint8 | 107.39 GiB |
| 256×256×3 float32 | 429.55 GiB |
| 224×224×3 float32 | 328.87 GiB |
| 每帧 512 维 float32 embedding | 1.12 GiB |
| 每帧 1024 维 float32 embedding | 2.24 GiB |

因此，当前任一本地卷都不适合新增完整 256 float32 图像缓存；D/E 也不够完整 256 uint8 缓存。未来视觉分支优先按需解码或生成声明版本的特征 embedding。冻结视觉骨干的 embedding 可用于时序头实验，但不能替代需要反向更新视觉骨干的端到端 RGB 训练。CE-CSL/TFNet 全模型训练需按实际 batch、保存策略、预处理另立预算；不能拿本轮 10 GiB 的特征模型预算作保证。

## 4. 场景属性应该放在哪里

指定会话中的需求仍适用：竞赛需要有限表达、确认纠错和可核查的共同语义。不过，该会话 10 月 9 日关于 T ZIP 不可读、中文尚未真实推理的状态已被后续数据审计与 TFNet/ONNX 基线推进更新，不能作为本轮现状。[场景语义覆盖审查](中巴手语竞赛_场景语义覆盖审查_2026-10-09.md)中的候选清单继续作为待审核选题。

当前代码实际状态：

- [SampleRecord 与 RecognitionResult](../slbridge/contracts.py) 没有专用场景/共同语义字段。
- [InferenceRequest](../slbridge/runtime_contracts.py) 和 [HTTP v1/v2](../slbridge/api.py) 未接收场景上下文。
- [CaptionCatalog v1](../slbridge/captions.py) 严格检查字段；直接给现有字幕 JSON 添加 `scene_ids` 会加载失败。
- [Libras 候选 CSV](reports/libras-scene-candidates-2026-10-09.csv) 已有 `scene_id`，审核状态为 `draft_source_text_only`；[中文候选 CSV](reports/csl-scene-candidates-2026-10-09.csv) 也明确未完成视频语义与跨手语等义审核。
- [共同语义审核清单](CE-CSL_Libras共同语义审核清单_2026-10-09.md) 要求审核双方视频、上下文和版本后才分配共同语义 ID，目前未开启生产映射。

建议独立设计如下契约；这是开发提案，不是已经被现有 API 接受的字段。

| 层 | 最小属性 | 用途 |
|---|---|---|
| 场景目录 | `scene_id`、中葡名称、定义、版本 | 校园、缴费等交际情境的稳定引用 |
| 数据注释旁表 | `dataset_id`、`sample_id` 或有命名空间的 `label_id`、`vocabulary_hash`、多值 `scene_ids`、注释版本/依据/审核状态 | 保留一个表达跨场景的可能性；不改原始标签和训练 manifest |
| 共同语义目录 | `semantic_id`、可选 `intent_id`、`scene_ids`、上下文限制、双方来源、映射版本、审核证据 | 审核后连接双方等义表达；未审不分配可用共同语义 |
| 会话 | `context.scene_id=null`、`source=unspecified/user_selected`、`revision` | 用户可不选择场景；首轮不自动猜测 |
| 应用 API 新封装 | 原样 `model_result`、请求开始时快照的 `context`、独立 `bridge` | 与已有 v1/v2 响应兼容共存；不将场景提示塞入模型张量 |
| 桥接结果 | `status=mapped/unreviewed/unmapped/ambiguous`、映射版本、审核证据、相应文本 | 未审核或歧义时给待审核/确认状态，不自动补成确定译文 |

旁表内容单独计算 hash；实验中登记所用旁表版本和 hash，避免无关场景注释改变历史模型的输入/数据身份。`label_id` 必须绑定数据集和词表版本，不能以裸整数连接两种手语。

四个维度保持独立：`sign_language` 是 CSL/Libras，`scene_id` 是交际情境，视频文件/摄像头是输入来源，CPU/CUDA 是运行配置。场景切换不应自动更换语言模型或要求模型重新训练。

例如来源条目 174“确认缴费”和 177“未缴费”都被候选 CSV 归入 `payment`，但必须保留不同语义和否定信息。它们目前也不在 12 类模型支持范围内。选择缴费场景不能使旧模型新增这两类；选择校园场景不能将电力客服句自动变成校园表达。

## 5. 对训练、热切换与验收的约束

首轮 Libras TCN 仍学习审核后的语言内词条/固定句式类别；中文保留 TFNet 基线，后续因果时序实验使用独立 CTC 任务头。场景先用于数据组织、补采规划与分层评价，不作为模型输入，不作为替代类别。是否以后按场景微调/使用上下文解码，要由充分标注和对照结果决定。

运行时先保留原始识别概率和序列。语义桥接可根据用户场景查询适用映射，但场景外、未知、歧义结果仍应允许回退；不能把场景外类别概率归零后强选一个场景内答案。场景查询不保证提高识别准确率，也未实测额外时延。

每次任务快照 `request_id + model_generation + session_epoch + context.revision + semantic_catalog_version`。已有运行时 generation 与会话 epoch 可复用；场景/目录版本需要补充。用户切场景后作废未提交的旧桥接解释，已提交历史保留原语境。模型/输入源切换需要重置相应流式状态；只改变展示语境时，无需清空与场景无关的 TCN 特征缓存。连续动作中改变语境要明确从哪一段开始生效。

后续实施应覆盖以下验收：

1. 没有场景属性时，原视频/摄像头与模型接口照常运行，旧模型包/字幕目录仍可读。
2. 用户选择场景时，原始识别结果不变；桥接展示带审核状态和目录版本。
3. 无场景、正确场景、错误场景、未知/跨场景表达分别评价，不用“知道答案”的场景提示证明模型效果。
4. 由真实标签或参考句整理的场景注释不能在测试时作为用户已知上下文输入，否则会泄漏目标信息。
5. 内容重复组和派生资产保持在同一 split；场景分组不能把 dev/test 混入训练。分别报告识别 accuracy/macro-F1 或 WER，以及桥接覆盖、错误映射、拒识、否定/数量误传。
6. 模型切换、场景切换和慢任务完成后，不出现旧结果按新语境覆盖当前字幕。

建议开发顺序为：来源/重复组与标签冻结 → 126/318 输入适配与小型 TCN 离线训练 → 独立场景/共同语义旁表 → 应用上下文与桥接封装 → 流式/摄像头及上下文切换验证。场景目录可与模型开发并行整理，不必等待完整场景应用，也不应阻塞核心识别基线。
